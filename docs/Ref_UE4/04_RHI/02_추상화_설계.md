# [4-2] RHI — 추상화 설계 분석

> 선행: [4-1] 결과 파일
> 대상: `RHI/` + `Windows/D3D11RHI/`
> 소스: UE4 4.27

---

## 1. FDynamicRHI → D3D11RHI 구현 매핑

### 1-1. 클래스 구조

```
FDynamicRHI (DynamicRHI.h:331)              ← RHI 추상 인터페이스
IRHICommandContextPSOFallback (RHIContext.h) ← PSO Fallback 컨텍스트
         ↑ (다중 상속)
FD3D11DynamicRHI (D3D11RHIPrivate.h:392)    ← D3D11 구현체
```

`FD3D11DynamicRHI`는 **FDynamicRHI + IRHICommandContextPSOFallback**을 다중 상속.
즉, 리소스 생성(FDynamicRHI)과 렌더링 명령 실행(IRHICommandContext)을 **단일 클래스에서 모두 구현**.

> D3D11은 Immediate Context가 단일이므로 RHI와 Context를 분리할 이유가 없다.
> 반면 Vulkan/D3D12는 멀티 커맨드 큐 지원으로 Context를 분리한다.

### 1-2. 구현 매핑 예시

#### 예시 1: RHICreateSamplerState (`D3D11State.cpp:132`)

```
FSamplerStateInitializerRHI (RHI 추상)
  → D3D11_SAMPLER_DESC 변환 (필터·주소 모드·LOD 등 필드 매핑)
    → ID3D11Device::CreateSamplerState()
      → FD3D11SamplerState (FRHISamplerState 상속) 반환
```

**핵심**: UE4 enum → D3D11 enum 변환 함수(`TranslateAddressMode`, `TranslateSamplerCompareFunction`)를 통해 매핑. `GSamplerStateCache`에 캐싱하여 동일 상태 재생성 방지.

#### 예시 2: RHICreateVertexBuffer (`D3D11VertexBuffer.cpp:17`)

```
(Size, Usage, CreateInfo) (RHI 추상)
  → D3D11_BUFFER_DESC 구성
    - BUF_AnyDynamic → D3D11_USAGE_DYNAMIC + D3D11_CPU_ACCESS_WRITE
    - BUF_UnorderedAccess → D3D11_BIND_UNORDERED_ACCESS 추가
    - BUF_ShaderResource → D3D11_BIND_SHADER_RESOURCE 추가
    - BUF_DrawIndirect → D3D11_RESOURCE_MISC_DRAWINDIRECT_ARGS
  → ID3D11Device::CreateBuffer()
    → FD3D11VertexBuffer (FRHIVertexBuffer + FD3D11BaseShaderResource 다중 상속)
        멤버: TRefCountPtr<ID3D11Buffer> Resource
```

**핵심**: UE4 `BUF_*` 플래그를 D3D11 `D3D11_BIND_FLAGS` / `D3D11_USAGE` / `D3D11_RESOURCE_MISC_FLAG`로 비트 매핑.

#### 예시 3: RHICreateTexture2D (`D3D11Texture.cpp:1221`)

```
(SizeX, SizeY, Format, NumMips, NumSamples, Flags, CreateInfo) (RHI 추상)
  → CreateD3D11Texture2D<FD3D11BaseTexture2D>() 템플릿 호출
    → DXGI_FORMAT 변환 (GPixelFormats[Format].PlatformFormat)
    → D3D11_TEXTURE2D_DESC 구성 (Usage, BindFlags, CPUAccess, MSAA 등)
    → SafeCreateTexture2D() → ID3D11Device::CreateTexture2D()
    → 필요 시 RTV/DSV/SRV 생성:
      - TexCreate_RenderTargetable → CreateRenderTargetView()
      - TexCreate_DepthStencilTargetable → CreateDepthStencilView()
      - SRV는 거의 항상 생성 → CreateShaderResourceView()
    → TD3D11Texture2D<FD3D11BaseTexture2D> 반환 (= FD3D11Texture2D typedef)
```

**핵심**: 하나의 `RHICreateTexture2D` 호출로 D3D11 텍스처 + 필요한 모든 뷰(RTV, DSV, SRV)를 한꺼번에 생성. 호출자는 뷰 생성을 신경 쓸 필요 없음.

#### 예시 4: RHIDrawIndexedPrimitive (`D3D11Commands.cpp`)

```
(IndexBuffer, BaseVertex, FirstInstance, NumVertices, StartIndex, NumPrimitives, NumInstances) (RHI)
  → ResourceCast<FRHIIndexBuffer>(IndexBuffer) → FD3D11IndexBuffer*
  → StateCache를 통해 상태 커밋 (필요한 경우만)
  → Direct3DDeviceIMContext->DrawIndexedInstanced(
      NumPrimitives * PrimVertexCount, NumInstances, StartIndex, BaseVertex, FirstInstance)
```

### 1-3. ResourceCast 패턴

```cpp
template<typename TRHIType>
static FORCEINLINE typename TD3D11ResourceTraits<TRHIType>::TConcreteType*
    ResourceCast(TRHIType* Resource)
{
    return static_cast<...>(Resource);
}
```

`TD3D11ResourceTraits`는 RHI 추상 타입 → D3D11 구체 타입 매핑 테이블:

| RHI 추상 | D3D11 구체 |
|----------|-----------|
| FRHITexture2D | FD3D11Texture2D |
| FRHITexture3D | FD3D11Texture3D |
| FRHITextureCube | FD3D11TextureCube |
| FRHIVertexBuffer | FD3D11VertexBuffer |
| FRHIIndexBuffer | FD3D11IndexBuffer |
| FRHIStructuredBuffer | FD3D11StructuredBuffer |
| FRHIUniformBuffer | FD3D11UniformBuffer |
| FRHIVertexShader | FD3D11VertexShader |
| FRHIPixelShader | FD3D11PixelShader |
| FRHIComputeShader | FD3D11ComputeShader |

> `static_cast` 사용 — RTTI 없이 **컴파일 타임에 안전한 다운캐스트**.
> D3D11 코드는 항상 자기가 생성한 리소스만 받으므로 안전함.

## 2. RHI 리소스 ↔ D3D11 리소스 래핑 구조

### 2-1. 버퍼 래핑 (다중 상속 패턴)

```
FRHIVertexBuffer (RHI 추상: Size, Usage)
FD3D11BaseShaderResource (IRefCountedObject)
        ↑ (다중 상속)
FD3D11VertexBuffer
  └── TRefCountPtr<ID3D11Buffer> Resource   ← 실제 D3D11 리소스
```

동일 패턴: `FD3D11IndexBuffer`, `FD3D11StructuredBuffer`

`FD3D11BaseShaderResource`는 SRV 바인딩 시 공통 인터페이스 역할.

### 2-2. 텍스처 래핑 (템플릿 + 다중 상속)

```
FRHITexture2D (RHI 추상: SizeX, SizeY, Format, NumMips ...)
  ↑ (상속)
FD3D11BaseTexture2D (= BaseResourceType, FRHITexture2D의 서브클래스)

FD3D11BaseShaderResource ← FD3D11TextureBase
  └── ID3D11Resource* Resource          ← 실제 D3D11 텍스처
  └── ID3D11ShaderResourceView* SRV     ← 기본 SRV
  └── TArray<ID3D11RenderTargetView*>   ← RTV (밉별)
  └── ID3D11DepthStencilView*[]         ← DSV (접근 타입별)
  └── int32 MemorySize

        ↑ (다중 상속)
TD3D11Texture2D<BaseResourceType>     ← 템플릿 클래스
```

**typedef를 통한 특수화:**
```cpp
typedef TD3D11Texture2D<FD3D11BaseTexture2D>      FD3D11Texture2D;      // 단일 2D 텍스처
typedef TD3D11Texture2D<FD3D11BaseTexture2DArray> FD3D11Texture2DArray; // 2D 배열
typedef TD3D11Texture2D<FD3D11BaseTextureCube>    FD3D11TextureCube;    // 큐브맵
```

> 템플릿으로 `BaseResourceType`만 바꾸면 3가지 텍스처 타입에 동일한 D3D11 리소스 관리 코드를 재사용.

### 2-3. 셰이더 래핑 (다중 상속 + 공유 데이터)

```
FRHIVertexShader (FRHIGraphicsShader → FRHIShader → FRHIResource)
FD3D11ShaderData (ShaderResourceTable, UniformBuffers, StaticSlots ...)
        ↑ (다중 상속)
FD3D11VertexShader
  └── TRefCountPtr<ID3D11VertexShader> Resource
  └── TArray<uint8> Code  (VS만 InputLayout 생성에 바이트코드 필요)
```

동일 패턴: `FD3D11PixelShader`, `FD3D11HullShader`, `FD3D11DomainShader`, `FD3D11GeometryShader`, `FD3D11ComputeShader`

`FD3D11ShaderData`가 셰이더 리소스 바인딩 메타데이터를 보유 — 리플렉션 정보 역할.

### 2-4. 뷰 래핑

```
FRHIShaderResourceView → FD3D11ShaderResourceView
  └── TRefCountPtr<ID3D11ShaderResourceView> View
  └── TRefCountPtr<FD3D11BaseShaderResource> Resource  ← 소유 리소스 참조

FRHIUnorderedAccessView → FD3D11UnorderedAccessView
  └── TRefCountPtr<ID3D11UnorderedAccessView> View
  └── TRefCountPtr<FD3D11BaseShaderResource> Resource  ← 소유 리소스 참조
```

## 3. RHICreateTexture2D() 전체 호출 체인

```
[엔진 코드] RHICreateTexture2D(SizeX, SizeY, Format, ...)
    ↓ (RHICommandList.h:5336 — FORCEINLINE 전역 함수)
GDynamicRHI->RHICreateTexture2D_RenderThread(ImmediateCommandList, ...)
    ↓ (D3D11Texture.cpp:1226 — D3D11은 RenderThread 변형이 직접 호출)
FD3D11DynamicRHI::RHICreateTexture2D(SizeX, SizeY, Format, NumMips, NumSamples, Flags, ...)
    ↓ (D3D11Texture.cpp:1222)
CreateD3D11Texture2D<FD3D11BaseTexture2D>(SizeX, SizeY, 1, false, false, Format, ...)
    ↓ (D3D11Texture.cpp:558 — 핵심 팩토리 템플릿 함수)
    │
    ├── [1] D3D11_TEXTURE2D_DESC 구성
    │   ├── Format → DXGI_FORMAT 변환 (GPixelFormats[].PlatformFormat)
    │   ├── Usage: TexCreate_CPUReadback → STAGING, Dynamic → DYNAMIC, else → DEFAULT
    │   ├── BindFlags: RT→RENDER_TARGET, DS→DEPTH_STENCIL, SRV→SHADER_RESOURCE
    │   └── MSAA: ActualMSAACount/Quality 결정
    │
    ├── [2] SafeCreateTexture2D(Direct3DDevice, ...) (D3D11Texture.cpp:509)
    │   └── ID3D11Device::CreateTexture2D(&Desc, SubResourceData, &TextureResource)
    │       ← 여기서 실제 GPU 메모리 할당 발생
    │
    ├── [3] RTV 생성 (TexCreate_RenderTargetable 플래그 시)
    │   └── ID3D11Device::CreateRenderTargetView() — 밉/슬라이스별
    │
    ├── [4] DSV 생성 (TexCreate_DepthStencilTargetable 플래그 시)
    │   └── ID3D11Device::CreateDepthStencilView() — FExclusiveDepthStencil 타입별 (최대 8개)
    │
    ├── [5] SRV 생성 (대부분의 텍스처)
    │   └── ID3D11Device::CreateShaderResourceView()
    │
    └── [6] TD3D11Texture2D<FD3D11BaseTexture2D> 생성자
        ├── BaseResourceType(SizeX, SizeY, ...) — FRHITexture2D 초기화
        └── FD3D11TextureBase(Resource, SRV, RTVs, DSVs) — D3D11 네이티브 핸들 저장

반환: FTexture2DRHIRef (= TRefCountPtr<FRHITexture2D>)
```

> **D3D11 특징**: `RHICreateTexture2D_RenderThread`가 `RHICreateTexture2D`를 직접 호출.
> ID3D11Device가 스레드 세이프이므로 RHI 스레드 동기화가 불필요하기 때문.

## 4. 추상화 구조의 장단점

### 장점

| 항목 | 설명 |
|------|------|
| **플랫폼 독립성** | 엔진 코드가 `RHICreateTexture2D()` 한 줄로 어떤 GPU API든 지원. 렌더러 코드 수정 없이 D3D11/D3D12/Vulkan/Metal 교체 가능 |
| **뷰 자동 생성** | 텍스처 생성 시 필요한 RTV/DSV/SRV를 플랫폼이 알아서 생성 → 호출자 복잡도 감소 |
| **타입 안전 캐스팅** | `TD3D11ResourceTraits` + `static_cast`로 RTTI 오버헤드 없이 안전한 다운캐스트 |
| **커맨드 리스트 추상화** | Bypass 모드(D3D11) / RHI 스레드(D3D12) / 비동기 컴퓨트를 동일 인터페이스로 |
| **상태 캐싱** | `GSamplerStateCache`, `StateCache` 등으로 중복 상태 생성/전환 최소화 |
| **_RenderThread 최적화** | 플랫폼별로 스레드 동기화 비용을 줄일 수 있는 별도 경로 제공 |

### 단점

| 항목 | 설명 |
|------|------|
| **다중 상속 복잡도** | D3D11 리소스가 RHI 추상 + BaseShaderResource를 다중 상속 → 다이아몬드 상속은 아니지만 코드 이해 비용 증가 |
| **최소 공통 분모 제약** | `FDynamicRHI`가 DX11 수준에 맞춰져 있어 DX12/Vulkan의 명시적 동기화, 메모리 관리 등을 직접 노출하기 어려움 |
| **가상 함수 오버헤드** | ~80개 이상의 가상 함수 → 핫 패스에서 간접 호출 비용. `final override`로 부분 완화 |
| **함수 폭증** | 매 함수마다 `_RenderThread`, `_BottomOfPipe` 변형이 있어 인터페이스가 비대함 |
| **플래그 매핑 산재** | `BUF_*` → `D3D11_BIND_FLAGS`, `TexCreate_*` → `D3D11_TEXTURE2D_DESC` 변환이 각 플랫폼에 산재 → 매핑 오류 위험 |
| **D3D11 Immediate Context 제약** | D3D11에서 RHI + Context를 단일 클래스로 구현 → 멀티스레드 제출 불가 (커맨드 리스트는 의미가 제한적) |

### 소규모 DX11 프레임워크 적용 시 고려사항

1. **FDynamicRHI 수준의 완전 추상화는 과잉** — DX11 전용이면 가상 함수 레이어 없이 직접 호출이 효율적
2. **텍스처 + 뷰 통합 생성은 참고할 만함** — 텍스처 생성 시 RTV/DSV/SRV를 함께 생성하는 패턴은 사용 편의성이 높음
3. **ResourceTraits 패턴** — 타입 매핑 테이블은 코드량이 적으면서 안전한 캐스팅 제공
4. **상태 캐싱** — D3D11은 동일 디스크립션에 동일 포인터를 반환하므로, 캐싱은 해시 비교 비용만큼의 가치만 있음
