# 작업 규칙

## 분석 가이드
- 분석 프롬프트 가이드: `origin/main`의 `docs/Ref_UE4/UE4_소스분석_프롬프트_가이드.md`
- "X-Y 실행" 지시 → 가이드에서 해당 ID 프롬프트를 찾아 실행
- 한 번에 하나의 작업(ID)만 실행한다. 절대 다음 작업을 자동으로 이어서 실행하지 않는다

## 브랜치·저장소 규칙
- **현재 작업 브랜치 외 새 브랜치 생성 절대 금지**
- **origin/main 클론(checkout/merge) 절대 금지**
- main 코드 확인: `git show origin/main:경로` 사용 (fetch 선행)
- 작업 결과 md 파일은 origin/main에 PR로 통합 관리
- **main 병합 작업 시 → WORKFLOW.md 섹션 4 체크리스트 반드시 읽고 따를 것**

## 문서 참고 규칙
- CLAUDE.md 관련이 아닌 프로젝트 문서는 항상 `origin/main`의 `docs/`에서 확인
  - `git show origin/main:docs/...` 명령 사용
- 원격 확인 전 반드시 `git fetch origin main` 선행

## 참고프로젝트 소스 탐색 규칙
- 참고프로젝트(UE4 등) 소스코드는 **origin/main에 포함**되어 있다
  - 경로: `참고프로젝트_UE4/`, `참고프로젝트1/` ~ `참고프로젝트4/`
  - 접근: `git show origin/main:참고프로젝트_UE4/...` 또는 `git ls-tree origin/main "참고프로젝트_UE4/..."`
- **웹 검색보다 origin/main의 실제 소스를 우선 확인**한다
- 모듈 존재 여부, 디렉터리 구조, 헤더 내용 등은 반드시 `git ls-tree` / `git show`로 먼저 확인
- 소스에서 확인 불가능한 경우에만 웹 검색을 보조적으로 사용

## 작업 규칙
1. 한 번에 하나의 작업(ID)만 실행한다. 절대 다음 작업을 자동으로 이어서 실행하지 않는다
2. 결과는 가이드에 명시된 경로에 마크다운으로 저장한다
3. 작업 완료 후 반드시 멈추고 결과를 요약 보고한다
4. 보고 형식:
   - 분석한 파일 수
   - 발견한 핵심 클래스/함수 수
   - 분석 중 불확실했던 부분
   - 저장 경로
5. 2단계(심화) 작업 시, 해당 모듈의 1단계 결과 파일을 반드시 먼저 읽는다
6. 소스코드에서 확인할 수 없는 내용은 추측하지 말고 "헤더만으로 확인 불가" 또는 "구현부 확인 필요"로 명시한다

## 할루시네이션 방지 규칙
- 클래스, 함수, 파일명을 언급할 때는 반드시 실제 소스코드에서 확인한 것만 적는다
- 해당 파일에서 직접 확인하지 못한 내용은 "미확인" 또는 "추정"으로 표시한다
- UE4 4.27 소스에 없는 UE5 전용 내용을 섞지 않는다
