## 2. RHI 리소스 타입 계층 (RHIResources.h)

```
FRHIResource (참조 카운팅 + 지연 삭제)
├── State Blocks
│   ├── FRHISamplerState
│   ├── FRHIRasterizerState
│   ├── FRHIDepthStencilState
│   └── FRHIBlendState
├── Shader Bindings
│   ├── FRHIVertexDeclaration

├── Shaders
│   └── FRHIShader (Hash, Frequency)
│       ├── FRHIGraphicsShader
│       │   ├── FRHIVertexShader (SF_Vertex)
│       │   ├── FRHIPixelShader (SF_Pixel)
│       │   ├── FRHIHullShader (SF_Hull)
│       │   ├── FRHIDomainShader (SF_Domain)
│       │   └── FRHIGeometryShader (SF_Geometry)
│       ├── FRHIComputeShader (SF_Compute)
│       └── FRHIRayTracingShader
├── Pipeline States
│   ├── FRHIGraphicsPipelineState
│   ├── FRHIComputePipelineState
│   └── FRHIRayTracingPipelineState
├── Buffers
│   ├── FRHIVertexBuffer (Size, Usage)

│       ├── FRHITexture3D (SizeX, SizeY, SizeZ)
│       ├── FRHITextureCube (Size)
│       └── FRHITextureReference (ReferencedTexture 간접 참조)
├── Views
│   ├── FRHIShaderResourceView (SRV)
│   └── FRHIUnorderedAccessView (UAV)
├── Synchronization

    └── FRHIRayTracingScene
```

### FRHIResource 기반 클래스 핵심 특징

- **참조 카운팅**: `AddRef()` / `Release()` — `FThreadSafeCounter` 사용, 스레드 안전
- **지연 삭제**: `DeferDelete()` 활성 시 `PendingDeletes` 리스트에 추가, 다음 프레임에서 삭제
  - GPU가 리소스 사용 완료를 보장하기 위해 비싼 펜스 대신 프레임 기반 지연 삭제 사용
- **커밋 상태 추적**: `SetCommitted()` / `IsCommitted()` — Transient 리소스 관리용

## 3. FRHICommandList의 역할과 구조 (RHICommandList.h)

### 클래스 계층

```
FRHICommandListBase (5738줄 파일의 핵심, FNoncopyable)
├── FRHIComputeCommandList (컴퓨트 전용 커맨드)
│   ├── FRHICommandList (그래픽스 + 컴퓨트 커맨드)
│   │   └── FRHICommandListImmediate (즉시 실행 싱글톤)
│   └── FRHIAsyncComputeCommandListImmediate (비동기 컴퓨트)
└── (IRHICommandContextContainer — 병렬 번역용)
```

### FRHICommandListBase — 핵심 구조

- **커맨드 링크드 리스트**: `FRHICommandBase* Root` → `Next` 체인
- **메모리 관리**: `FMemStackBase MemManager` — 스택 기반 빠른 할당
- **커맨드 추가**: `AllocCommand<TCmd>()` → 메모리 할당 후 링크드 리스트에 연결
- **커맨드 실행**: `FRHICommandBase::ExecuteAndDestruct()` 가상 함수 호출
- **바이패스 모드**: `Bypass()` — RHI 스레드 없을 시 커맨드 큐잉 없이 직접 실행
- **GPU 마스크**: `FRHIGPUMask GPUMask` — Multi-GPU 지원
- **커맨드 실행 컨텍스트**: `IRHICommandContext* Context` / `IRHIComputeContext* ComputeContext`

### FRHIComputeCommandList — 컴퓨트 커맨드

- `SetShaderUniformBuffer`, `SetShaderParameter`, `SetShaderTexture`, `SetShaderSampler`
- `SetUAVParameter`, `SetShaderResourceViewParameter`
- `DispatchComputeShader`, `DispatchIndirectComputeShader`

### FRHICommandList — 그래픽스 커맨드 (FRHIComputeCommandList 상속)

- 바운드 셰이더 접근: `GetBoundVertexShader()`, `GetBoundPixelShader()` 등
- 그래픽스 전용: `SetViewport`, `SetScissorRect`, `SetStreamSource`
- Draw Call: `DrawPrimitive`, `DrawIndexedPrimitive`, `DrawPrimitiveIndirect`, `DrawIndexedPrimitiveIndirect`
- 렌더 패스: `BeginRenderPass`, `EndRenderPass`
- 상태 설정: `SetGraphicsPipelineState`, `SetStencilRef`, `SetBlendFactor`

### FRHICommandListImmediate — 즉시 실행 전용

- **싱글톤 패턴**: `FRHICommandListExecutor`가 하나만 보유
- `ImmediateFlush(FlushType)` — 커맨드 즉시 제출
- `StallRHIThread()` / `UnStallRHIThread()` — RHI 스레드 동기화
- `RHIThreadFence()` — 병렬 번역 완료 대기
- `EnqueueLambda()` — 람다 기반 커맨드 추가
- 리소스 직접 생성 메서드: `CreateSamplerState()`, `CreateTexture2D()` 등 래퍼 제공

### 실행 컨텍스트 (RHIContext.h)

```
IRHIComputeContext (컴퓨트 기본 인터페이스)
├── SetComputeShader, DispatchComputeShader
├── SetShaderTexture/Sampler/UAV/SRV/UniformBuffer/Parameter
├── ClearUAVFloat/ClearUAVUint
└── BeginTransitions/EndTransitions

IRHICommandContext : IRHIComputeContext (그래픽스 확장)
├── Draw: DrawPrimitive, DrawIndexedPrimitive, DrawPrimitiveIndirect, DrawIndexedPrimitiveIndirect, DrawIndexedIndirect
├── 상태: SetViewport, SetScissorRect, SetGraphicsPipelineState, SetStreamSource
├── 렌더 패스: BeginRenderPass, EndRenderPass
├── 프레임: BeginFrame/EndFrame, BeginScene/EndScene
├── 뷰포트: BeginDrawingViewport, EndDrawingViewport
└── 텍스처: CopyToResolveTarget, CopyTexture, UpdateTextureReference
```

### 커맨드 패턴 (바이패스 vs 큐잉)

```cpp
// 각 함수가 동일한 패턴을 따름
void SetShaderTexture(FRHIComputeShader* Shader, ...) {
    if (Bypass()) {
        GetComputeContext().RHISetShaderTexture(Shader, ...); // 직접 실행
        return;
    }
    ALLOC_COMMAND(FRHICommandSetShaderTexture)(Shader, ...); // 큐잉
}
```

## 4. ERHIFeatureLevel 정의와 각 레벨의 의미 (RHIDefinitions.h)

```cpp
namespace ERHIFeatureLevel
{
    enum Type
    {
        ES2_REMOVED,   // OpenGL ES2 (제거됨, UE4.27에서 비활성)
        ES3_1,         // OpenGL ES3.1 / Metal / Vulkan 기본 수준
        SM4_REMOVED,   // DX10 SM4 (제거됨)
        SM5,           // DX11 SM5 — 사실상 UE4.27의 기본 데스크탑 수준
        Num            // 열거값 개수
    };
};
```

### SM5 (Shader Model 5) 포함 기능

소스 주석에 명시된 SM5의 구체적 기능:

- **컴퓨트 셰이더**: 공유 메모리(groupshared), 그룹 동기화(GroupMemoryBarrier), UAV 쓰기, 정수 아토믹
- **간접 드로잉**: `DrawPrimitiveIndirect`, `DrawIndexedPrimitiveIndirect`
- **픽셀 셰이더 UAV 쓰기**: PS에서 UAV 직접 쓰기 가능
- **큐브맵 배열**: TextureCubeArray 지원
- **읽기 전용 깊이/스텐실 뷰**: 깊이 버퍼를 SRV로 읽으면서 동시에 깊이 테스트 + 스텐실 쓰기 가능

> **참고**: 테셀레이션(Hull/Domain Shader)은 SM5 Feature Level에 포함되지 않으며, 별도의 capability 플래그로 관리된다.

### 프레임워크 참고 사항

DX11 기반 프레임워크에서는 **SM5만 지원하면 충분**하다. ES3_1은 모바일용이며, ES2/SM4는 이미 UE4.27에서 제거되었다.

## 프레임워크 설계 시 참고 포인트

### FDynamicRHI 패턴 적용

- **인터페이스 분리**: 리소스 생성(Factory)과 커맨드 실행(Context)이 분리됨
  - `FDynamicRHI` = 리소스 팩토리 (Create 계열)
  - `IRHICommandContext` = 커맨드 실행 (Set/Draw/Dispatch 계열)
- **전역 접근점**: `GDynamicRHI` 포인터 + 인라인 래퍼 함수 (`RHICreateTexture2D()` 등)
- DX11 전용이라면 인터페이스를 단순화할 수 있으나, 추후 Vulkan/DX12 확장 고려 시 이 분리 패턴 유지 권장

### 리소스 수명 관리

- **참조 카운팅 + 지연 삭제**: GPU 사용 완료 보장을 위한 프레임 기반 지연
- 프레임워크의 기존 참조 카운팅 패턴과 자연스럽게 통합 가능

### 커맨드 리스트 패턴

- **바이패스 패턴**: 싱글 스레드일 때 큐잉 없이 직접 실행 → 성능 최적화
- **커맨드 큐**: 멀티 스레드 렌더링 시 게임 스레드에서 커맨드 기록, RHI 스레드에서 실행
- 초기 프레임워크에서는 바이패스(즉시 실행) 모드만 구현 후 필요 시 커맨드 큐잉 추가 가능
