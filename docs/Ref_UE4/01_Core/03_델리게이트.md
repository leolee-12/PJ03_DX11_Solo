# [1-3] Core — 델리게이트 심화 분석

> 분석 대상: UE4 4.27 `Runtime/Core/Public/Delegates/`
> 주요 파일: DelegateCombinations.h, DelegateSignatureImpl.inl, DelegateBase.h, DelegateInstancesImpl.h, MulticastDelegateBase.h

---

## 쉬운 개념 가이드

**델리게이트란?**
- "이벤트가 발생하면 이 함수를 호출해줘"라고 등록하는 시스템
- 비유: **알람 앱** — "아침 7시가 되면 이 소리를 울려줘"라고 등록하면, 시간이 되면 자동 실행

**왜 필요한가?**
- 게임에서 "적이 죽으면 점수 올려, 이펙트 재생해, 사운드 틀어"처럼 **하나의 이벤트에 여러 반응**이 필요
- 점수 시스템이 적 클래스를 직접 알 필요 없이, 델리게이트로 느슨하게 연결

**핵심 비유:**
| 개념 | 비유 |
|------|------|
| 싱글캐스트 | 전화 1대 — 번호 1개만 저장 |
| 멀티캐스트 | 단체 문자 — 여러 명에게 동시 전송 |
| Broadcast() | "단체 문자 보내기" 버튼 |
| Bind/Add | 연락처에 번호 등록 |
| Unbind/Remove | 연락처에서 번호 삭제 |
| FDelegateHandle | 등록 영수증 — 나중에 이걸로 삭제 가능 |
| Type Erasure | 전화번호부가 상대방이 아이폰인지 갤럭시인지 몰라도 전화를 걸 수 있는 것 |
| Payload | 전화할 때 항상 함께 전달하는 메모 (추가 인자) |

## 1. DECLARE_DELEGATE 매크로 전개 과정

> 델리게이트를 선언할 때 `DECLARE_DELEGATE` 매크로를 사용한다.
> 이 매크로는 **새로운 타입(typedef)을 만들 뿐**, 런타임 비용은 없다.

```
DECLARE_DELEGATE(FMyDelegate)
  → typedef TDelegate<void()> FMyDelegate;
     ↑ "인자 없고 반환값 없는 함수를 1개 등록할 수 있는 타입"

DECLARE_DELEGATE_OneParam(FMyDelegate, int32)
  → typedef TDelegate<void(int32)> FMyDelegate;
     ↑ "int32 인자 1개를 받는 함수를 등록할 수 있는 타입"

DECLARE_DELEGATE_RetVal(float, FMyDelegate)
  → typedef TDelegate<float()> FMyDelegate;
     ↑ "float를 반환하는 함수를 등록할 수 있는 타입"
```

### 매크로 변형 패턴

| 매크로 | 만들어지는 타입 | 용도 |
|--------|----------------|------|
| `DECLARE_DELEGATE` | `TDelegate<void()>` | 함수 1개 등록 |
| `DECLARE_MULTICAST_DELEGATE` | `TMulticastDelegate<void()>` | 함수 여러 개 등록 |
| `DECLARE_DYNAMIC_DELEGATE` | UHT 생성 코드 | 블루프린트에서도 사용 가능 |

- 파라미터 수: 0~9개 지원 (`_OneParam` ~ `_NineParams`)
- 반환값: `_RetVal` 접미사 (싱글캐스트만, 멀티캐스트는 void만 가능)
- Dynamic 전용: 파라미터 **이름**도 같이 적어야 함 (`int32, Value`)

## 2. 싱글캐스트 vs 멀티캐스트 vs 다이나믹

| 항목 | Singlecast | Multicast | Dynamic |
|------|-----------|-----------|---------|
| **등록 가능 수** | 1개 | 여러 개 | 여러 개 (Dynamic Multicast) |
| **반환값** | 가능 | **불가** (void만) | 가능 (단일만) |
| **호출 방법** | `Execute()` | `Broadcast()` | `ProcessEvent()` 경유 |
| **블루프린트** | 불가 | 불가 | 가능 |
| **속도** | 빠름 | 빠름 | 느림 (리플렉션 경유) |

### 상속 구조 (싱글캐스트)

```
FDelegateBase                      ← 메모리 관리 (등록된 함수를 저장하는 공간)
  └─ TDelegateBase                 ← 바인딩 여부 확인, 핸들 관리
       └─ TDelegate<void(Params...)>
            ← Execute(), Bind*()     ← 실제 사용하는 함수들
```

### 상속 구조 (멀티캐스트)

```
TMulticastDelegateBase             ← 등록 목록(InvocationList) 관리
  └─ TMulticastDelegate<void(Params...)>
       ← Add*(), Remove(), Broadcast()
```

## 3. 바인딩 타입별 저장 구조

> "어떤 종류의 함수를 등록했느냐"에 따라 내부 저장 방식이 다르다.

### 공통 구조

```cpp
class 바인딩인스턴스 {
    TTuple<VarTypes...> Payload;     // Bind 시 미리 전달한 추가 인자들
    FDelegateHandle Handle;          // 이 바인딩의 고유 번호 (삭제할 때 사용)
};
```

### 바인딩 타입별 비교

| 타입 | 무엇을 등록? | 안전성 | 비유 |
|------|------------|--------|------|
| **Raw** | 일반 객체의 멤버 함수 | 위험 (객체 삭제 후 호출하면 크래시) | 주소만 적어둔 전화번호 — 이사하면 못 찾음 |
| **SP** | 스마트 포인터 객체의 멤버 함수 | 안전 (WeakPtr로 유효성 확인) | 자동 업데이트되는 연락처 |
| **UObject** | UObject의 멤버 함수 (포인터 직접) | 안전 (WeakObjectPtr) | UE4 전용 자동 관리 연락처 |
| **Static** | 전역/static 함수 | 항상 안전 (삭제될 일 없음) | 119 같은 고정 번호 |
| **Functor** | 람다/함수 객체 (문서에서 Lambda로 표기) | 캡처 변수에 따라 다름 | 메모에 적어둔 임시 번호 |
| **UFunction** | UObject의 멤버 함수 (FName으로 참조) | 안전 (WeakObjectPtr) | UE4 블루프린트 전용 |

### 메모리 할당

- 기본값: 항상 **힙 할당** (`FHeapAllocator`) — `NUM_DELEGATE_INLINE_BYTES` 미정의 시
- 인라인 저장: `NUM_DELEGATE_INLINE_BYTES`를 16의 배수로 정의하면 `TInlineAllocator`로 전환 (힙 할당 회피)
- Win32에서는 16바이트 정렬 값 전달 불가로 인라인 미지원, 항상 힙 할당
- `TAlignedBytes<16, 16>` — 16바이트 정렬 블록 단위로 관리

## 4. 델리게이트 실행 흐름

### 싱글캐스트: Execute

```
MyDelegate.Execute(인자들)
  → 내부에 저장된 함수 인스턴스 꺼내기
  → 인스턴스가 nullptr이면 크래시 (checkSlow)
  → 인스턴스의 Execute() 호출 → 등록된 함수 실행
```

### 싱글캐스트: ExecuteIfBound (안전 버전)

```
MyDelegate.ExecuteIfBound(인자들)
  → 인스턴스가 nullptr이면 → 아무것도 안 하고 false 반환
  → 있으면 → ExecuteIfSafe() 호출 (SP는 WeakPtr 유효성도 확인)
```

### 멀티캐스트: Broadcast ★핵심★

```
MyMulticastDelegate.Broadcast(인자들)
  → 목록 잠금 (Lock)         ← Broadcast 중 목록이 바뀌는 것 방지
  → 등록 목록을 역순으로 순회 (끝 → 처음)
      → 각 인스턴스의 ExecuteIfSafe() 호출
      → 실패(이미 삭제된 객체 등)하면 "정리 필요" 표시
  → 목록 잠금 해제 (Unlock)
  → 정리 필요 시 → 실패한 항목 제거 (Compact)
```

**왜 역순으로 순회하나?**
- Broadcast 실행 중에 새로운 함수가 Add되면 목록 끝에 추가됨
- 역순 순회이므로 **이번 Broadcast에서는 새로 추가된 것을 호출하지 않음** → 예측 가능한 동작

**왜 Lock을 사용하나?**
- Broadcast 중에 Remove가 호출되면 목록이 꼬일 수 있음
- Lock으로 즉시 삭제를 막고, Broadcast 끝나고 한 번에 정리 (Lock-Compact 패턴)

## 5. 프레임워크 적용 시 핵심 참고사항

1. **매크로 → typedef**: `DECLARE_DELEGATE`는 컴파일 타임에 타입만 만듦, 런타임 비용 없음
2. **Type Erasure**: 다양한 바인딩 타입을 하나의 저장소(FDelegateBase)에 보관하는 기법
3. **Payload (커링)**: Bind 시 추가 인자를 미리 저장 → 호출 시 자동 전달
4. **역순 Broadcast**: 실행 중 추가된 함수의 즉시 호출 방지
5. **Lock-Compact**: 반복 중 안전한 수정을 위한 패턴

### DX11 프레임워크 적용 시 고려사항
- UObject/UFunction/블루프린트 관련은 제외 → **Raw/SP/Lambda/Static만 구현**
- 인라인 저장소(16바이트)로 작은 바인딩의 힙 할당 회피
- 참조 카운팅 연동: SP 바인딩이 TWeakPtr 사용 → 프레임워크의 참조 카운팅과 통합 가능
