## 1. SGraphEditor 핵심 구조 (노드, 핀, 연결)

### 시나리오 1: 머티리얼 에디터에서 노드 그래프를 열 때

```
[사용자] 콘텐츠 브라우저에서 Material 더블클릭
  │
  ▼
[UnrealEd] UAssetEditorSubsystem::OpenEditorForAsset(Material)
  │  ← Material 타입 → IMaterialEditor(FAssetEditorToolkit) 생성
  ▼
[MaterialEditor] InitMaterialEditor()
  │
  ├─ UMaterialGraph 생성 (UEdGraph 상속)
  │    ← 왜: 노드/핀/연결의 데이터 모델 역할
  │
  ├─ UMaterialGraph::RebuildGraph()
  │    ← 왜: Material의 Expression 목록을 UEdGraphNode로 변환
  │
  ▼
[GraphEditorModule] PRIVATE_MakeGraphEditor(GraphToEdit=MaterialGraph, ...)
  │  ← 왜: SGraphEditor는 모듈이 팩토리 메서드로 생성
  ▼
[SGraphEditorImpl] Construct()
  │
  ├─ SGraphPanel 생성 (실제 노드/연결 렌더링 담당)
  │    ← 왜: SNodePanel 상속, 줌/팬/선택/드래그 처리
  │
  ├─ SGraphPanel::Construct(GraphObj=MaterialGraph)
  │    ← 왜: UEdGraph의 Nodes 배열을 순회하여 SGraphNode 위젯 생성
  │
  └─ 각 UEdGraphNode에 대해:
       ├─ FNodeFactory::CreateNodeWidget(Node) → SGraphNode 파생 위젯
       │    ← 왜: 노드 타입별 전용 Slate 위젯 생성 (팩토리 패턴)
       │
       └─ SGraphNode::CreatePinWidgets()
            ← 왜: 노드의 Pins 배열을 순회하여 SGraphPin 위젯 생성
```

### 1.1 계층 구조

```
SGraphEditor (공개 인터페이스, SCompoundWidget)
  └─ SGraphEditorImpl (Private 구현체)
       ├─ SOverlay (TitleBar + GraphPanel)
       └─ SGraphPanel (SNodePanel 상속, FGCObject)
            ├─ SGraphNode[] (각 노드 위젯)
            │    └─ SGraphPin[] (각 핀 위젯)
            └─ FConnectionDrawingPolicy (연결선 렌더링)
```

### 1.2 데이터 모델 vs 뷰 위젯

| 데이터 모델 (Runtime) | 뷰 위젯 (Editor) | 역할 |
|----------------------|-------------------|------|
| `UEdGraph` | `SGraphPanel` | 그래프 전체 |
| `UEdGraphNode` | `SGraphNode` | 개별 노드 |
| `UEdGraphPin` | `SGraphPin` | 개별 핀 |
| `UEdGraphPin::LinkedTo[]` | `FConnectionDrawingPolicy` | 연결선 |
| `UEdGraphSchema` | — | 그래프 규칙/검증 |

### 1.3 SGraphPanel 핵심 기능

| 기능 | 구현 |
|------|------|
| 노드 추가 | `AddNode(UEdGraphNode*, Behavior)` → `FNodeFactory::CreateNodeWidget` |
| 노드 제거 | `RemoveNode(UEdGraphNode*)` |
| 연결선 렌더링 | `OnPaint()` 내에서 `FConnectionDrawingPolicy::DrawConnection()` |
| 컨텍스트 메뉴 | `SummonContextMenu()` → `FOnGetContextMenuFor` 델리게이트 |
| 줌/팬 | `SNodePanel` 기본 기능 상속 (마우스 휠, 중클릭 드래그) |
| 선택 | 마우스 클릭 + `FOnSelectionChanged` 델리게이트 |
| 마키 선택 | `FMarqueeOperation` (드래그 박스) |
| 드래그 앤 드롭 | `OnDrop()` → 에셋/액터를 노드로 변환 |

## 2. UEdGraphNode → UEdGraphPin 관계

### 2.1 UEdGraphNode 핵심 멤버

```
UEdGraphNode : UObject
  │
  ├─ TArray<UEdGraphPin*> Pins        ← 이 노드의 모든 핀
  ├─ int32 NodePosX, NodePosY          ← 에디터 내 위치
  ├─ int32 NodeWidth, NodeHeight       ← 리사이즈 가능 노드용
  ├─ FGuid NodeGuid                    ← 고유 식별자 (diff 용)
  ├─ ENodeEnabledState EnabledState    ← 활성/비활성/개발전용
  ├─ FString NodeComment               ← 노드 코멘트
  └─ uint8 bHasCompilerMessage         ← 컴파일 에러/경고 플래그
```

**핵심 가상 메서드:**

| 메서드 | 역할 |
|--------|------|
| `AllocateDefaultPins()` | 노드 생성 시 기본 핀 구성 |
| `ReconstructNode()` | 핀 재구성 (타입 변경 등 시) |
| `GetNodeTitle(TitleType)` | 노드 제목 반환 (Full/ListView/Editable/Menu) |
| `GetTooltipText()` | 툴팁 텍스트 |
| `GetNodeContextMenuActions()` | 컨텍스트 메뉴 항목 구성 |
| `AutowireNewNode(FromPin)` | 드래그로 생성된 노드 자동 연결 |
| `PinConnectionListChanged(Pin)` | 핀 연결 변경 시 콜백 |
| `NodeConnectionListChanged()` | 노드의 연결 상태 변경 시 콜백 |
| `PostPlacedNewNode()` | 새 노드 배치 직후 초기화 |
| `CanUserDeleteNode()` | 사용자 삭제 가능 여부 |
| `CanSplitPin(Pin)` | 핀 분리 가능 여부 (예: Vector → X,Y,Z) |

### 2.2 UEdGraphPin 핵심 멤버

```
UEdGraphPin (UObject가 아닌 일반 C++ 클래스)
  │
  ├─ UEdGraphNode* OwningNode          ← 소유 노드 (private)
  ├─ FGuid PinId                       ← 고유 식별자
  ├─ FName PinName                     ← 핀 이름
  ├─ EEdGraphPinDirection Direction    ← Input / Output
  ├─ FEdGraphPinType PinType           ← 타입 정보
  │    ├─ FName PinCategory            ← 대분류 (exec, bool, float, object 등)
  │    ├─ FName PinSubCategory         ← 소분류
  │    ├─ UObject* PinSubCategoryObject ← 타입 오브젝트 (UClass* 등)
  │    ├─ EPinContainerType ContainerType ← None/Array/Set/Map
  │    └─ bIsReference, bIsConst       ← 참조/상수 여부
  │
  ├─ TArray<UEdGraphPin*> LinkedTo     ← 연결된 핀 목록
  ├─ TArray<UEdGraphPin*> SubPins      ← 분리된 서브핀 (Vector → X,Y,Z)
  ├─ UEdGraphPin* ParentPin            ← 분리 원본 핀
  │
  ├─ FString DefaultValue              ← 기본값 (문자열)
  ├─ UObject* DefaultObject            ← 기본값 (오브젝트)
  ├─ FText DefaultTextValue            ← 기본값 (텍스트)
  │
  └─ uint8 bHidden, bNotConnectable    ← 숨김/연결불가 플래그
```

**핵심 메서드:**

| 메서드 | 역할 |
|--------|------|
| `MakeLinkTo(ToPin)` | 핀 간 연결 생성 (양방향 LinkedTo 추가) |
| `BreakLinkTo(ToPin)` | 특정 핀과의 연결 해제 |
| `BreakAllPinLinks()` | 모든 연결 해제 |
| `HasAnyConnections()` | 연결 존재 여부 (SubPins 포함) |
| `GetOwningNode()` | 소유 노드 반환 |
| `GetSchema()` | 그래프 스키마 접근 |
| `FindPin(Name, Direction)` | 이름으로 핀 검색 (UEdGraphNode) |

### 2.3 소유 관계

```
UEdGraph::Nodes[] ──owns──▶ UEdGraphNode (UObject 서브오브젝트)
                                │
                                ├─ Pins[] ──owns──▶ UEdGraphPin (일반 C++ 객체, 풀링)
                                │                      │
                                │                      ├─ LinkedTo[] ──ref──▶ UEdGraphPin (다른 노드의 핀)
                                │                      └─ SubPins[] ──owns──▶ UEdGraphPin
                                │
                                └─ SubGraphs[] ──owns──▶ UEdGraph (자식 그래프)
```

- `UEdGraphPin`은 `UObject`가 아닌 일반 C++ 클래스 (4.17 이후)
- 핀은 내부적으로 풀링(`PooledPins`)하여 메모리 할당 최적화
- `FEdGraphPinReference`(USTRUCT)로 안전한 핀 참조 (OwningNode WeakPtr + PinId)

## 3. 노드 생성/삭제/연결 흐름

### 시나리오 2: 우클릭 → 컨텍스트 메뉴에서 노드 추가

```
[사용자] 그래프 빈 공간에서 우클릭
  │
  ▼
[SGraphPanel] OnMouseButtonUp() → SummonContextMenu()
  │  ← 왜: 그래프 좌표와 드래그 소스 핀 정보를 수집
  │
  ├─ FGraphContextMenuArguments 구성
  │    ├─ NodeAddPosition (그래프 좌표)
  │    ├─ GraphNode (null: 빈 공간)
  │    ├─ GraphPin (null: 핀 드래그 없음)
  │    └─ DragFromPins[] (드래그 소스 핀들)
  │
  ▼
[SGraphEditorImpl] FOnGetContextMenuFor 델리게이트 호출
  │  ← 왜: 그래프 타입에 맞는 메뉴 생성을 위임
  │
  ▼
[UEdGraphSchema] GetGraphContextActions(ContextMenuBuilder)
  │  ← 왜: 스키마가 허용하는 노드 액션 목록을 생성
  │
  ├─ FEdGraphSchemaAction 파생 인스턴스 목록 반환
  │    예: FMaterialGraphSchemaAction_NewNode (머티리얼)
  │    예: FBlueprintActionMenuItem (블루프린트)
  │
  ▼
[SGraphActionMenu] 메뉴 표시 → 사용자가 항목 선택
  │
  ▼
[FEdGraphSchemaAction] PerformAction(ParentGraph, FromPin, Location)
  │  ← 왜: 선택된 액션이 실제 노드 생성을 수행
  │
  ├─ UEdGraphNode 서브클래스 인스턴스 생성
  │    (예: UMaterialGraphNode, UK2Node_CallFunction)
  │
  ├─ Node->AllocateDefaultPins()
  │    ← 왜: 노드 타입에 맞는 기본 Input/Output 핀 생성
  │
  ├─ UEdGraph::AddNode(Node, bUserAction=true)
  │    ← 왜: Nodes 배열에 추가 + OnGraphChanged 델리게이트 브로드캐스트
  │
  ├─ Node->AutowireNewNode(FromPin)
  │    ← 왜: 드래그 소스 핀이 있으면 자동 연결
  │
  └─ Node->PostPlacedNewNode()
       ← 왜: 배치 후 초기화 (미리보기 설정 등)
  │
  ▼
[SGraphPanel] NotifyGraphChanged() → Update()
  │  ← 왜: 데이터 변경을 감지하여 위젯 동기화
  │
  └─ AddNode() → FNodeFactory::CreateNodeWidget(Node) → SGraphNode 생성
       ← 왜: 새 UEdGraphNode에 대응하는 Slate 위젯 생성
```

### 시나리오 3: 핀 드래그로 연결 생성

```
[사용자] Output 핀에서 마우스 드래그 시작
  │
  ▼
[SGraphPin] OnMouseButtonDown() → OnPinMouseDown()
  │
  ▼
[SGraphPanel] OnBeginMakingConnection(OriginatingPin)
  │  ← 왜: 프리뷰 연결선 렌더링 시작
  │
  ├─ PreviewConnectorFromPins에 소스 핀 저장
  └─ 매 프레임 OnPaint()에서 프리뷰 연결선 그리기
  │
  ▼
[사용자] 다른 노드의 Input 핀 위에 드롭
  │
  ▼
[SGraphPin] OnDrop() → 연결 시도
  │
  ▼
[UEdGraphSchema] CanCreateConnection(PinA, PinB)
  │  ← 왜: 스키마가 연결 호환성 검증
  │
  ├─ FPinConnectionResponse 반환
  │    ├─ CONNECT_RESPONSE_MAKE (허용)
  │    ├─ CONNECT_RESPONSE_DISALLOW (거부)
  │    ├─ CONNECT_RESPONSE_BREAK_OTHERS_A (기존 연결 끊고 새 연결)
  │    └─ CONNECT_RESPONSE_MAKE_WITH_CONVERSION_NODE (변환 노드 삽입)
  │
  ▼
[UEdGraphSchema] TryCreateConnection(PinA, PinB)
  │
  ├─ PinA->MakeLinkTo(PinB)
  │    ← 왜: 양쪽 핀의 LinkedTo 배열에 상호 참조 추가
  │
  └─ 각 노드의 PinConnectionListChanged() 호출
       ← 왜: 노드가 연결 변경에 반응 (핀 추가/제거 등)
```

### 시나리오 4: 노드 삭제

```
[사용자] 노드 선택 → Delete 키
  │
  ▼
[SGraphEditorImpl] DeleteSelectedNodes 커맨드 실행
  │
  ▼
[UEdGraphSchema] BreakNodeLinks(TargetNode)
  │  ← 왜: 삭제 전 모든 핀 연결 해제

  │
```

### 3.1 FGraphNodeCreator (안전한 노드 생성 패턴)

```cpp
// 트랜잭션 패턴: 생성 + Finalize를 보장
FGraphNodeCreator<UMaterialGraphNode> Creator(*Graph);
UMaterialGraphNode* Node = Creator.CreateNode(/*bSelectNewNode=*/true);
Node->MaterialExpression = Expression;
Creator.Finalize(); // AllocateDefaultPins() + AddNode() + 통지
```

- `CreateNode()`: 노드 생성 (아직 그래프에 미등록)
- `Finalize()`: 핀 할당 + 그래프 등록 + OnGraphChanged 호출
- RAII 패턴으로 Finalize 누락 방지

## 4. UEdGraphSchema — 그래프 규칙 시스템

### 4.1 핵심 역할

`UEdGraphSchema`는 그래프의 "규칙집"으로, 어떤 노드/연결이 허용되는지 결정.

| 메서드 | 역할 |
|--------|------|
| `GetGraphContextActions()` | 우클릭 메뉴에 표시할 액션 목록 |
| `GetContextMenuActions()` | 노드/핀 컨텍스트 메뉴 |
| `CanCreateConnection(A, B)` | 두 핀 간 연결 가능 여부 + 응답 타입 |
| `TryCreateConnection(A, B)` | 실제 연결 생성 (검증 포함) |
| `BreakNodeLinks()` | 노드의 모든 연결 해제 |
| `BreakPinLinks()` | 핀의 모든 연결 해제 |
| `GetPinTypeColor(PinType)` | 핀 타입별 색상 반환 |
| `ShouldHidePinDefaultValue(Pin)` | 기본값 입력 숨김 여부 |
| `DroppedAssetsOnGraph()` | 에셋 드래그앤드롭 시 노드 생성 |
| `SafeDeleteNodeFromGraph()` | 노드 안전 삭제 |

### 4.2 FEdGraphSchemaAction — 노드 생성 액션

```
FEdGraphSchemaAction (기본 액션)
  ├─ MenuDescription, Category, Keywords  ← 메뉴 표시 정보
  ├─ Grouping, SectionID                  ← 정렬/그룹 정보
  └─ PerformAction(Graph, FromPin, Loc)   ← 실제 노드 생성 실행
       │
       ├─ FMaterialGraphSchemaAction_NewNode      (머티리얼 노드)
       ├─ FMaterialGraphSchemaAction_NewFunctionCall  (머티리얼 함수)
       ├─ FMaterialGraphSchemaAction_NewComment    (코멘트)
       ├─ FMaterialGraphSchemaAction_Paste         (붙여넣기)
       └─ FBlueprintActionMenuItem                 (블루프린트 노드)
```

### 4.3 스키마 파생 관계

```
UEdGraphSchema (Engine, 기본 스키마)
  ├─ UMaterialGraphSchema (UnrealEd, 머티리얼 전용)
  │    ← 핀 카테고리: PC_Mask, PC_Required, PC_Optional, PC_MaterialInput
  │    ← 핀 색상: ActivePinColor, InactivePinColor, AlphaPinColor
  │
  └─ UEdGraphSchema_K2 (BlueprintGraph, 블루프린트 전용)
       ← 핀 카테고리: PC_Exec, PC_Boolean, PC_Byte, PC_Int, PC_Float, PC_Object 등
       ← 타입 호환성 검증, 자동 캐스팅, Exec 핀 흐름 관리
```

## 5. 머티리얼 에디터의 GraphEditor 활용

### 5.1 UMaterialGraph (UEdGraph 상속)

```
UMaterialGraph : UEdGraph
  │
  ├─ UMaterial* Material               ← 편집 중인 머티리얼
  ├─ UMaterialFunction* MaterialFunction ← 함수 편집 시
  ├─ UMaterialGraphNode_Root* RootNode ← 루트 노드 (머티리얼 입력 핀)
  ├─ TArray<FMaterialInputInfo> MaterialInputs  ← 머티리얼 입력 정보
  │
  ├─ RebuildGraph()                    ← 전체 그래프 재구축
  ├─ AddExpression(UMaterialExpression*) → UMaterialGraphNode*
  ├─ AddComment(UMaterialExpressionComment*) → UMaterialGraphNode_Comment*
  ├─ LinkGraphNodesFromMaterial()      ← Material → Graph 동기화
  └─ LinkMaterialExpressionsFromGraph() ← Graph → Material 동기화
```

### 5.2 노드 클래스 계층

```
UEdGraphNode (Engine)
  └─ UMaterialGraphNode_Base (UnrealEd)
       ├─ UMaterialGraphNode          ← 일반 Expression 노드
       │    └─ UMaterialExpression* MaterialExpression (실제 데이터)
       ├─ UMaterialGraphNode_Root     ← 최종 출력 노드 (삭제 불가)
       └─ UMaterialGraphNode_Comment  ← 코멘트 노드
```

### 5.3 양방향 동기화 구조

머티리얼 에디터는 **데이터 모델이 이중**으로 존재:

```
[UMaterial]                      [UMaterialGraph (UEdGraph)]
  │                                │
  ├─ Expressions[]  ◄═══════════►  ├─ Nodes[] (UMaterialGraphNode)
  │    └─ FExpressionInput         │    └─ UEdGraphPin::LinkedTo[]
  │       (InputIndex 기반 연결)    │       (핀 참조 기반 연결)
  │                                │
  └─ 컴파일/렌더링에 사용           └─ 에디터 UI에 사용
```

- `LinkGraphNodesFromMaterial()`: Material의 Expression 연결을 EdGraphPin 연결로 변환
- `LinkMaterialExpressionsFromGraph()`: EdGraphPin 연결을 Material Expression 연결로 역변환
- 사용자가 핀을 연결/해제하면 Graph → Material 방향으로 동기화

### 5.4 머티리얼 노드 위젯 (SGraphNodeMaterialBase)

```
SGraphNode (GraphEditor)
  └─ SGraphNodeMaterialBase (Private)
       ├─ SGraphNodeMaterialResult   ← 루트 노드 전용 위젯
       └─ (기본 SGraphNodeMaterialBase) ← Expression 노드 위젯
            └─ 미리보기 렌더링 지원 (FMaterialRenderProxy)
```

- `FNodeFactory::CreateNodeWidget()`가 노드 타입을 보고 적절한 SGraphNode 파생 위젯 생성
- 머티리얼 노드는 Expression 미리보기 텍스처를 렌더링하는 기능 추가

### 5.5 FConnectionDrawingPolicy 커스터마이징

```
FConnectionDrawingPolicy (기본 연결선 정책)
  ├─ FMaterialGraphConnectionDrawingPolicy  (머티리얼 전용)
  │    ← 핀 타입에 따라 선 색상/두께 변경
  │
  └─ FKismetConnectionDrawingPolicy (블루프린트 전용)
       ← Exec 핀은 흰색 실선, 데이터 핀은 타입별 색상
```

- `FNodeFactory::CreateConnectionPolicy(Schema, ...)`: 스키마 타입별 연결선 정책 생성
- 연결선은 OnPaint에서 매 프레임 렌더링 (스플라인 곡선)

## 6. 블루프린트 에디터(Kismet)의 GraphEditor 활용

### 6.1 FBlueprintEditor (FAssetEditorToolkit)

```
FBlueprintEditor
  │
  ├─ TWeakPtr<SGraphEditor> FocusedGraphEdPtr  ← 현재 포커스된 그래프
  ├─ TWeakPtr<FDocumentTabFactory> GraphEditorTabFactoryPtr ← 그래프 탭 팩토리

  │    ← 왜: 블루프린트는 여러 그래프를 탭으로 관리 (EventGraph, 함수별 그래프)
  │
  ├─ SetupGraphEditorEvents(EdGraph, Events)

  │
  └─ GetGraphAppearance(EdGraph) → FGraphAppearanceInfo
       ← 왜: 그래프 타입에 따라 외형 설정 (배경색, 코너 텍스트 등)
```

### 6.2 UK2Node (UEdGraphNode 상속)

블루프린트 노드의 기본 클래스:

```
UEdGraphNode
  └─ UK2Node (abstract)
       ├─ UK2Node_CallFunction      ← 함수 호출 노드
       ├─ UK2Node_Event              ← 이벤트 노드 (BeginPlay 등)
       ├─ UK2Node_IfThenElse         ← 분기 노드
       ├─ UK2Node_Variable...        ← 변수 Get/Set 노드
       ├─ UK2Node_AddComponent       ← 컴포넌트 추가 노드
       └─ 수십 개의 K2Node 파생 클래스
```

**UK2Node 추가 기능:**

| 메서드 | 역할 |
|--------|------|
| `ExpandNode(Compiler, Graph)` | 컴파일 시 노드 확장 (매크로 → 실제 노드) |
| `GetMenuActions(Registrar)` | 블루프린트 액션 데이터베이스에 등록 |
| `IsNodePure()` | 순수 함수 여부 (Exec 핀 없음) |
| `ShouldShowNodeProperties()` | 디테일 패널에 프로퍼티 표시 여부 |
| `ValidateNodeDuringCompilation(MessageLog)` | 컴파일 시 노드 유효성 검증 (FCompilerResultsLog에 결과 기록) |
| `RenameUserDefinedPin()` | 사용자 정의 핀 이름 변경 |

### 6.3 블루프린트 컴파일 연동

```
[사용자] 블루프린트 컴파일 버튼 클릭
  │
  ▼
[Kismet] FBlueprintCompilationManager::CompileSynchronously(Request)
  │
  ├─ FBPCompileRequest
  │    ├─ BPToCompile: UBlueprint*
  │    ├─ CompileOptions: EBlueprintCompileOptions

  ├─ FlushCompilationQueue()
  │    ← 왜: 의존성 있는 블루프린트를 올바른 순서로 컴파일
  │
  └─ RegisterCompilerExtension()
       ← 왜: 블루프린트 타입별 커스텀 컴파일러 확장 등록
```

## 7. ImGui 노드 에디터 구현 시 참고 구조

### 7.1 핵심 매핑

| UE4 구조 | ImGui 대응 | 비고 |
|----------|-----------|------|
| `UEdGraph` | 노드/핀/링크 데이터 컨테이너 | 직접 구현 필요 |
| `UEdGraphNode` | Node ID + 위치 + 핀 목록 | 구조체로 정의 |
| `UEdGraphPin` | Pin ID + 타입 + 방향 + 연결 목록 | 구조체로 정의 |
| `UEdGraphSchema` | 연결 규칙 검증 인터페이스 | 그래프 타입별 구현 |
| `SGraphPanel` | ImNodes/imnodes 라이브러리 활용 | 렌더링 + 인터랙션 |
| `SGraphNode` | ImNodes의 `BeginNode/EndNode` | 즉시 모드 렌더링 |
| `SGraphPin` | ImNodes의 `BeginPin/EndPin` | 입출력 구분 |
| `FConnectionDrawingPolicy` | ImNodes 내장 또는 커스텀 베지어 곡선 | ImDrawList 활용 |
| `FNodeFactory` | 타입별 렌더링 함수 테이블 | `map<TypeID, DrawFunc>` |
| `FEdGraphSchemaAction` | 노드 생성 커맨드 패턴 | 메뉴 항목 + 생성 함수 |

### 7.2 최소 구현 설계

```
1. 데이터 모델 (UEdGraph/Node/Pin 대응)
   ├─ NodeGraph { vector<Node>, vector<Link> }
   ├─ Node { ID, Pos, vector<Pin>, 타입정보 }
   ├─ Pin { ID, Direction, Type, DefaultValue }
   └─ Link { OutputPinID, InputPinID }

2. 스키마 (UEdGraphSchema 대응)
   └─ IGraphSchema {
        CanConnect(PinA, PinB) → Response
        GetContextActions(Filter) → vector<Action>
        GetPinColor(PinType) → Color
      }

3. 액션 시스템 (FEdGraphSchemaAction 대응)
   └─ INodeAction {
        GetName(), GetCategory()
        Execute(Graph, Position) → Node*
      }

4. 렌더링 (SGraphPanel + SGraphNode 대응)
   └─ ImNodes 라이브러리 활용
      ├─ BeginNodeEditor() / EndNodeEditor()
      ├─ 각 노드: BeginNode(ID) / EndNode()
      ├─ 각 핀: BeginInputAttribute(ID) / EndInputAttribute()
      └─ 링크: Link(ID, StartPinID, EndPinID)

5. 양방향 동기화 (머티리얼 에디터 패턴 참고)
   └─ 도메인 데이터 ⟷ 그래프 데이터 동기화 레이어
```

### 7.3 UE4에서 배울 핵심 패턴

1. **데이터/뷰 분리**: `UEdGraph`(데이터) ↔ `SGraphPanel`(뷰) 완전 분리
2. **스키마 패턴**: 그래프 규칙을 별도 클래스로 분리 → 타입별 교체 가능
3. **팩토리 패턴**: `FNodeFactory`로 노드 타입별 위젯 생성 위임
4. **액션 패턴**: 노드 생성을 `FEdGraphSchemaAction::PerformAction()`으로 캡슐화
5. **양방향 동기화**: 도메인 모델 ↔ 그래프 모델 간 명시적 동기화 함수
