# [14-1] Editor — 구조 파악

> 분석 대상: UE4 4.27 `Source/Editor/` 중 UnrealEd, MainFrame, LevelEditor, ContentBrowser, PropertyEditor, DetailCustomizations 모듈
> 주요 파일: 각 모듈의 Public/ 디렉토리 .h 파일

---

## 1. 에디터 메인 프레임의 탭/패널 구조

### 시나리오 1: 에디터가 처음 실행될 때

```
[OS] WinMain()
  │
  ▼
[Launch] FEngineLoop::PreInit()
  │  엔진 기본 모듈 로드 (Core, CoreUObject, Engine 등)
  ▼
[Launch] FEngineLoop::Init()
  │  UEditorEngine 초기화
  ▼
[UnrealEd] UEditorEngine::Init()
  │  에디터 전용 서브시스템 초기화 (UAssetEditorSubsystem 등)
  ▼
[MainFrame] IMainFrameModule::CreateDefaultMainFrame(bImmersive, bPIE)
  │  ← 왜: OS 윈도우(SWindow)를 생성하고 FGlobalTabmanager에 루트 탭을 등록하기 위해
  │
  ├─ SWindow 생성 (OS 네이티브 윈도우)
  │    ← 왜: 모든 Slate 위젯이 올라갈 최상위 컨테이너
  │
  ├─ FGlobalTabmanager에 메인 SDockTab 등록
  │    ← 왜: 탭 기반 도킹 시스템의 루트 노드 역할
  │
  └─ MakeMainMenu() / MakeMainTabMenu() 호출
       ← 왜: File, Edit, Window 등 글로벌 메뉴 바 생성
  │
  ▼
[LevelEditor] FLevelEditorModule::StartupModule()
  │  ← 왜: 레벨 에디터 탭 스포너(Tab Spawner)를 FGlobalTabmanager에 등록
  │
  ├─ RegisterTabSpawner("LevelEditorViewport")
  │    ← 왜: 뷰포트 탭이 요청될 때 SLevelViewport를 생성하는 팩토리 등록
  │
  ├─ RegisterTabSpawner("LevelEditorSelectionDetails")
  │    ← 왜: 디테일 패널 탭 요청 시 IDetailsView 기반 위젯 생성
  │
  ├─ RegisterTabSpawner("LevelEditorSceneOutliner")
  │    ← 왜: 씬 아웃라이너 탭 생성
  │
  ├─ RegisterTabSpawner("ContentBrowser")
  │    ← 왜: 콘텐츠 브라우저 탭 생성
  │
  └─ RegisterTabSpawner("OutputLog", "WorldSettings", ...)
       ← 왜: 기타 에디터 패널들
  │
  ▼
[LevelEditor] SLevelEditor 생성 (ILevelEditor + IToolkitHost 구현)
  │  ← 왜: 레벨 에디터의 메인 Slate 컴포짓 위젯이자 에셋 에디터 호스트
  │
  ├─ FTabManager::RestoreFrom(SavedLayout)
  │    ← 왜: 사용자가 마지막으로 저장한 탭 배치를 복원
  │
  └─ 기본 레이아웃 적용 (Viewport 중앙, Details 우측, Outliner 좌측 등)
       ← 왜: 저장된 레이아웃이 없을 때의 폴백 배치
  │
  ▼
[MainFrame] FMainFrameCreationFinishedEvent 브로드캐스트
  │  ← 왜: 다른 모듈에게 메인 프레임 준비 완료를 알림
  ▼
[DetailCustomizations] FDetailCustomizationsModule::StartupModule()
  │  ← 왜: 내장 타입별 커스텀 디테일 에디터를 PropertyEditor에 일괄 등록
  │
  ├─ RegisterObjectCustomizations()
  │    ← 왜: AActor, ACamera 등 클래스별 디테일 패널 커스터마이징 등록
  │
  └─ RegisterPropertyTypeCustomizations()
       ← 왜: FLinearColor, FVector 등 구조체별 위젯 커스터마이징 등록
```

### 1.1 모듈 계층

```
IMainFrameModule (MainFrame)
  └─ SWindow (OS 창)
       └─ FGlobalTabmanager
            └─ SDockTab (메인 탭)
                 └─ ILevelEditor (SLevelEditor)
                      ├─ Viewport 탭 (SLevelViewport)
                      ├─ Details 탭 (IDetailsView)
                      ├─ SceneOutliner 탭
                      ├─ ContentBrowser 탭
                      ├─ OutputLog 탭
                      ├─ WorldSettings 탭
                      └─ Sequencer 탭 등
```

### 1.2 IMainFrameModule (MainFrame 모듈)

| 메서드 | 역할 |
|--------|------|
| `CreateDefaultMainFrame(bStartImmersive, bStartPIE)` | 에디터 메인 윈도우 생성 (Immersive/PIE 옵션) |
| `RecreateDefaultMainFrame(bStartImmersive, bStartPIE)` | 기존 메인 프레임 정리 후 재생성 (동일 파라미터) |
| `MakeMainMenu()` | 글로벌 메뉴 위젯 생성 (FTabManager + FToolMenuContext 기반) |
| `MakeMainTabMenu()` | 메인 탭 전용 확장 메뉴 생성 |
| `MakeDeveloperTools()` | 상태 바 개발자 도구 위젯 생성 |
| `SetLevelNameForWindowTitle()` | 타이틀 바 레벨명 갱신 |
| `RequestCloseEditor()` | 에디터 종료 요청 (저장 다이얼로그 가능) |

- `FMainFrameCreationFinishedEvent`: 메인 프레임 생성 완료 시 이벤트 (`DECLARE_EVENT_TwoParams`, `TSharedPtr<SWindow>` + `bool`)
- `FMainFrameCanCloseEditor`: 에디터 종료 허용 여부 **RetVal 델리게이트** (`DECLARE_DELEGATE_RetVal(bool)`), 다수 등록 가능

### 1.3 FLevelEditorModule (LevelEditor 모듈)

에디터의 핵심 모듈. `IModuleInterface` + `IHasMenuExtensibility` + `IHasToolBarExtensibility`를 구현.

**등록된 탭 ID (`LevelEditorTabIds`):**

| 탭 ID | 역할 |
|--------|------|
| `LevelEditorViewport` (+ Clone1~4) | 3D 뷰포트 (최대 5개) |
| `LevelEditorToolBar` | 상단 툴바 |
| `LevelEditorSelectionDetails` (+ 2~4) | 선택된 액터 디테일 패널 |
| `PlacementBrowser` | 배치 브라우저 (액터 드래그 배치) |
| `LevelEditorSceneOutliner` | 씬 아웃라이너 |
| `Sequencer` | 시퀀서 |
| `WorldSettings` | 월드 세팅 |
| `OutputLog` | 출력 로그 |
| `LevelEditorToolBox` | 에디터 모드 도구상자 |
| `LevelEditorBuildAndSubmit` | 빌드 및 제출 |
| `LevelEditorStatsViewer` | 통계 뷰어 |
| `LevelEditorLayerBrowser` | 레이어 브라우저 |
| `SequencerGraphEditor` | 시퀀서 그래프 에디터 |
| `WorldBrowserComposition` | 월드 컴포지션 |
| `WorldBrowserHierarchy` | 월드 계층 |
| `WorldBrowserDetails` | 월드 디테일 |
| `LevelEditorHierarchicalLODOutliner` | HLOD 아웃라이너 |
| `LevelEditorEnvironmentLightingViewer` | 환경 라이팅 뷰어 |

**핵심 이벤트:**

| 이벤트 | 역할 |
|--------|------|
| `FActorSelectionChangedEvent` | 액터 선택 변경 시 (디테일 패널 갱신 트리거) |
| `FOnLevelEditorCreated` | 레벨 에디터 인스턴스 생성 완료 시 |
| `FMapChangedEvent` | 맵 변경 시 |
| `FTabManagerChangedEvent` | 탭 매니저 변경 시 |
| `FOnRegisterTabs` | 탭 등록 시점 |

### 1.4 ILevelEditor (SLevelEditor의 공개 인터페이스)

`SCompoundWidget` + `IToolkitHost`를 동시 상속. 레벨 에디터의 Slate 위젯이자 툴킷 호스트.

| 메서드 | 역할 |
|--------|------|
| `GetViewports()` | 모든 뷰포트 목록 반환 |
| `GetActiveViewportInterface()` | 활성 뷰포트 반환 |
| `CreateActorDetails()` | 액터 디테일 위젯 생성 |
| `SetActorDetailsRootCustomization()` | 디테일 패널의 오브젝트 필터/루트 커스터마이징 설정 |
| `CreateToolBox()` | 에디터 모드 도구상자 위젯 생성 |
| `GetSceneOutliner()` | 씬 아웃라이너 접근 |

> **참고**: `GetTabManager()`는 ILevelEditor.h에 직접 선언되어 있지 않음. 탭 매니저 접근은 `FLevelEditorModule::GetLevelEditorTabManager()`를 통해 가능.

### 1.5 Toolkit 시스템

```
IToolkit                          ← 모든 에디터 도구의 인터페이스
  ├─ FBaseToolkit                 ← 기본 구현
  │    └─ FAssetEditorToolkit     ← 에셋 에디터 기본 (IAssetEditorInstance + FBaseToolkit)
  └─ (EdMode 관련 툴킷)
```

| EToolkitMode | 설명 |
|-------------|------|
| `Standalone` | 독립 윈도우 에셋 에디터 |
| `WorldCentric` | 레벨 에디터 내 통합 |

| EToolkitTabSpot | 위치 |
|----------------|------|
| `Details` | 프로퍼티/디테일 영역 |
| `Document` | 문서 영역 (그래프, 프로파일링 등) |
| `Navigation` | 탐색 패널 (서브오브젝트 목록 등) |
| `ToolBar` | 상단 좁은 툴바 |
| `Placement` | 배치 패널 |
| `Viewport` | 프리뷰 뷰포트 |
| `BelowLevelEditor` | 레벨 에디터 하단 영역 |

**FExtensibilityManager**: 메뉴/툴바 확장 관리. `TArray<TSharedPtr<FExtender>>`를 통합하여 반환.

## 2. 콘텐츠 브라우저의 에셋 표시/필터링 구조

### 시나리오 3: 콘텐츠 브라우저에서 에셋을 검색하고 더블클릭할 때

```
[사용자] 콘텐츠 브라우저 검색창에 "MyMaterial" 입력
  │
  ▼
[ContentBrowser] SContentBrowser::OnSearchBoxChanged("MyMaterial")
  │  ← 왜: 사용자 입력을 검색 필터로 변환하기 위해
  │
  ├─ FContentBrowserModule::FOnSearchBoxChanged 델리게이트 브로드캐스트
  │    ← 왜: 외부 모듈에게 검색어 변경을 알림
  │
  ▼
[ContentBrowser] 필터 체인 적용 (3단계)
  │
  ├─ 1단계: FARFilter 구성 (Backend 필터)
  │    ← 왜: AssetRegistry에서 클래스/경로/태그 기준으로 1차 필터링
  │    │  ClassNames, PackagePaths, Tags 등으로 후보 에셋 축소
  │    ▼
  │    IAssetRegistry::GetAssets(FARFilter) → TArray<FAssetData>
  │
  ├─ 2단계: FFrontendFilter 적용 (Frontend 필터)
  │    ← 왜: UI에서 사용자가 활성화한 커스텀 필터 적용 (예: "Modified Assets Only")
  │    │  IFilter<FAssetFilterType>::PassesFilter(FAssetData) → bool (베이스 클래스에서 상속)
  │    ▼
  │    활성화된 모든 FFrontendFilter를 AND 조합으로 적용
  │
  └─ 3단계: 텍스트 검색 매칭
       ← 왜: 사용자가 입력한 "MyMaterial"과 에셋 이름/경로를 문자열 매칭
  │
  ▼
[ContentBrowser] SAssetView에 필터링된 결과 표시
  │  ← 왜: 뷰 모드(List/Tile/Column)에 따라 에셋 목록 렌더링
  │
  ├─ FAssetData → 썸네일 생성 요청 (FAssetThumbnail)
  │    ← 왜: Tile 뷰에서 에셋 프리뷰 이미지 표시
  │
  └─ FOnFilterChanged 델리게이트 브로드캐스트
       ← 왜: 외부에서 현재 필터 상태를 추적할 수 있도록
  │
  ▼
[사용자] "MyMaterial" 에셋을 더블클릭
  │
  ▼
[ContentBrowser] SAssetView::OnAssetDoubleClicked(FAssetData)
  │  ← 왜: 더블클릭 이벤트를 에셋 에디터 오픈 요청으로 변환
  │
  ▼
[UnrealEd] UAssetEditorSubsystem::OpenEditorForAsset(UObject* Asset)
  │  ← 왜: 에셋 타입에 맞는 에디터를 찾아 실행
  │
  ├─ FindEditorForAsset(Asset) → 이미 열려 있으면 FocusWindow()
  │    ← 왜: 동일 에셋의 중복 에디터 방지
  │
  └─ 에셋 타입별 FAssetEditorToolkit 생성
       ← 왜: Material → MaterialEditor, Blueprint → BlueprintEditor 등 전용 에디터
  │
  ▼
[FAssetEditorToolkit] InitAssetEditor()
  │
  ├─ EToolkitMode::Standalone → 독립 SWindow 생성
  │    ← 왜: 별도 윈도우에서 에셋 전용 에디터 표시
  │
  └─ EToolkitMode::WorldCentric → IToolkitHost(SLevelEditor)에 탭 추가
       ← 왜: 레벨 에디터 내에 통합 표시
  │
  ▼
[UnrealEd] FOnAssetOpenedInEditorEvent 브로드캐스트
  │  ← 왜: 에셋 에디터가 열렸음을 다른 시스템에 알림
```

### 2.1 모듈 구조

```
FContentBrowserModule : IModuleInterface
  └─ IContentBrowserSingleton (싱글톤 인터페이스)
       └─ SContentBrowser (실제 Slate 위젯, Private)
            ├─ SPathView (폴더 트리)
            ├─ SAssetView (에셋 목록 — List/Tile/Column 뷰)
            └─ SFilterList (필터 UI)
```

### 2.2 에셋 표시 구조

**뷰 모드 (`EAssetViewType`):**

| 모드 | 설명 |
|------|------|
| `List` | 목록형 |
| `Tile` | 타일형 (썸네일 포함) |
| `Column` | 컬럼형 (상세 정보 표) |

**FContentBrowserConfig**: 콘텐츠 브라우저 인스턴스별 설정

| 설정 | 기본값 | 설명 |
|------|--------|------|
| `ThumbnailLabel` | `ClassName` | 썸네일 라벨 내용 |
| `ThumbnailScale` | 0.1 | 썸네일 기본 크기 |
| `InitialAssetViewType` | `Tile` | 초기 뷰 모드 |
| `bUseSourcesView` | true | 폴더/컬렉션 소스 뷰 표시 |
| `bCanShowFilters` | true | 필터 UI 표시 |
| `bCanShowFolders` | true | 폴더 표시 옵션 |

### 2.3 필터링 시스템

**레이어별 필터:**

| 레이어 | 클래스 | 역할 |
|--------|--------|------|
| Backend 필터 | `FARFilter` | AssetRegistry 수준 필터 (클래스, 경로, 태그) |
| Frontend 필터 | `FFrontendFilter` | UI 수준 커스텀 필터 (IFilter 인터페이스) |
| Plugin 필터 | `FContentBrowserPluginFilter` | 외부 플러그인 필터 확장 |

**FFrontendFilter 인터페이스:**

```cpp
class FFrontendFilter : public IFilter<FAssetFilterType> {
    // FFrontendFilter 고유 메서드
    virtual FString GetName() const = 0;
    virtual FText GetDisplayName() const = 0;
    virtual bool IsInverseFilter() const;
    virtual void SetCurrentFilter(TArrayView<const FName> InSourcePaths,
                                  const FContentBrowserDataFilter& InBaseFilter);
    // PassesFilter()는 베이스 클래스 IFilter<FAssetFilterType>에서 상속
};
```

- `FFrontendFilterCategory`: 필터를 카테고리별로 그룹핑
- `FOnShouldFilterAsset`: 외부에서 에셋 필터링 콜백 등록 (true 반환 시 제외)

### 2.4 확장 델리게이트

| 델리게이트 | 역할 |
|------------|------|
| `FOnFilterChanged` | 필터 변경 시 |
| `FOnSearchBoxChanged` | 검색어 변경 시 |
| `FOnAssetSelectionChanged` | 에셋 선택 변경 시 |
| `FOnSourcesViewChanged` | 소스 뷰 확장/축소 시 |
| `FOnAssetPathChanged` | 경로 변경 시 |
| `FAssetViewExtraStateGenerator` | 에셋 아이콘 위에 추가 상태 표시 |
| `FAssetViewDragAndDropExtender` | 드래그앤드롭 확장 |

## 3. 프로퍼티 에디터의 디테일 패널 생성 흐름

### 시나리오 2: 사용자가 뷰포트에서 액터를 클릭할 때

```
[사용자] 뷰포트에서 StaticMeshActor를 클릭
  │
  ▼
[Engine] SLevelViewport에서 마우스 클릭 → HitProxy 판정
  │  ← 왜: 3D 공간의 클릭 좌표를 어떤 액터에 해당하는지 판별
  │
  ▼
[UnrealEd] UEditorEngine::SelectActor(Actor, bSelected=true, bNotify=true)
  │  ← 왜: 클릭된 액터를 에디터의 선택 목록(USelection)에 추가
  │
  ├─ USelection에 액터 추가/제거
  │    ← 왜: 에디터 전역 선택 상태를 USelection 오브젝트가 관리
  │
  └─ NoteSelectionChange(bNotify=true)
       ← 왜: 선택이 실제로 변경되었음을 에디터 시스템에 통지
  │
  ▼
[LevelEditor] FLevelEditorModule::BroadcastActorSelectionChanged(NewSelection)
  │  ← 왜: 선택 변경을 구독 중인 모든 패널(디테일, 아웃라이너 등)에 알림
  │
  ├─ FActorSelectionChangedEvent 델리게이트 호출
  │    ← 왜: 이벤트 기반 느슨한 결합으로 패널 간 직접 참조 방지
  │
  ▼
[PropertyEditor] IDetailsView (bUpdatesFromSelection=true인 인스턴스)
  │  ← 왜: 선택과 동기화되는 디테일 패널이 새 오브젝트를 수신
  │
  ▼
[PropertyEditor] IDetailsView::SetObjects(SelectedActors)
  │  ← 왜: 디테일 패널에 표시할 오브젝트 목록을 갱신
  │
  ▼
[PropertyEditor] FDetailLayoutBuilderImpl 생성
  │  ← 왜: UObject의 리플렉션 정보를 읽어 UI 레이아웃을 구축하는 빌더
  │
  ├─ UClass::PropertyLink 순회 (FProperty 체인)
  │    ← 왜: UPROPERTY()로 선언된 모든 프로퍼티를 열거
  │
  ├─ 각 FProperty에서 Category 메타데이터 읽기
  │    ← 왜: "Transform", "Rendering" 등 카테고리별로 그룹핑
  │
  ├─ FCustomDetailLayoutMap에서 커스텀 레이아웃 검색
  │    ← 왜: RegisterCustomClassLayout으로 등록된 커스터마이징 확인
  │
  └─ GenerateDetailLayout()
       ← 왜: 모든 프로퍼티/커스텀 행을 Slate 위젯 트리로 변환
  │
  ▼
[PropertyEditor] 각 프로퍼티에 대해 IPropertyHandle 생성
  │  ← 왜: 값 읽기/쓰기를 Pre/PostEditChange + Undo 트랜잭션과 함께 처리
  │
  └─ 타입별 위젯 생성
       ├─ float → SSpinBox
       ├─ FVector → SNumericVectorInputBox
       ├─ FLinearColor → SColorPicker (커스텀 타입 레이아웃)
       └─ bool → SCheckBox
       ← 왜: 프로퍼티 타입에 맞는 최적의 편집 UI 제공
  │
  ▼
[사용자] 디테일 패널에서 Location.X 값을 수정 (100 → 200)
  │
  ▼
[PropertyEditor] IPropertyHandle::SetValue(200.0f)
  │  ← 왜: 값 변경을 안전하게 처리하기 위해
  │
  ├─ GEditor->BeginTransaction("Set Location.X")
  │    ← 왜: Undo/Redo를 위한 트랜잭션 시작
  │
  ├─ Actor->PreEditChange(Property)
  │    ← 왜: 변경 전 상태 저장 (트랜잭션 레코드에 기록)
  │
  ├─ 실제 메모리에 값 쓰기 (FProperty::SetValue_InContainer)
  │    ← 왜: UObject 메모리 레이아웃의 올바른 오프셋에 값 반영
  │
  ├─ Actor->PostEditChangeProperty(FPropertyChangedEvent)
  │    ← 왜: 변경 사항 반영 (예: Transform 변경 시 물리 바디 갱신)
  │
  └─ GEditor->EndTransaction()
       ← 왜: 트랜잭션 종료, Undo 스택에 기록 완료
  │
  ▼
[PropertyEditor] FOnFinishedChangingProperties 델리게이트 호출
  │  ← 왜: PostEditChange 이후 안전한 시점에서 추가 처리 (UI 갱신 등)
  │
  ▼
[Engine] 뷰포트에 액터 위치 변경 반영 (다음 프레임 렌더링)
```

### 3.1 핵심 클래스 관계

```
FPropertyEditorModule
  ├─ RegisterCustomClassLayout(ClassName, Delegate)      ← 클래스별 커스텀 레이아웃
  ├─ RegisterCustomPropertyTypeLayout(TypeName, Delegate) ← 타입별 커스텀 레이아웃
  └─ CreateDetailView(FDetailsViewArgs) → IDetailsView*

IDetailsView : SCompoundWidget
  └─ SetObjects(TArray<UObject*>)  ← 표시할 오브젝트 설정
       → FDetailLayoutBuilderImpl 생성
            → 리플렉션으로 프로퍼티 열거
            → 카테고리별 정리
            → 커스터마이징 적용
            → Slate 위젯 트리 생성
```

### 3.2 디테일 패널 생성 흐름

```
1. SetObjects(Objects)
   → UObject 목록 설정

2. FDetailLayoutBuilderImpl 생성
   → FComplexPropertyNode (루트)에서 FClassToPropertyMap 구성
   → UClass의 리플렉션 정보(FProperty 체인)를 순회

3. GenerateDetailLayout()
   → 각 FProperty에 대해:
     a. 카테고리 결정 (프로퍼티의 Category 메타데이터)
     b. FDetailCategoryImpl::DefaultCategory()로 카테고리 생성/편집
     c. 커스텀 클래스 레이아웃 검색 (RegisterCustomClassLayout 등록분)
     d. 커스텀 타입 레이아웃 검색 (RegisterCustomPropertyTypeLayout 등록분)
     e. 커스텀 없으면 기본 FDetailPropertyRow 생성

4. Slate 위젯 트리 구성
   → DetailTreeNode → DetailItemNode → SWidget 매핑
   → IPropertyHandle을 통해 값 읽기/쓰기
```

### 3.3 IPropertyHandle — 리플렉션 접근 핸들

프로퍼티 값의 읽기/쓰기를 Pre/PostEditChange, 트랜잭션, 패키지 수정과 함께 처리.

| 메서드 | 역할 |
|--------|------|
| `GetProperty()` | `FProperty*` 반환 (리플렉션 정보) |
| `GetValue()/SetValue()` | 값 읽기/쓰기 |
| `HasMetaData(Key)` | UPROPERTY 메타데이터 조회 |
| `GetNumChildren()` | 자식 프로퍼티 수 |
| `GetChildHandle()` | 자식 핸들 접근 |
| `IsEditConst()` | 편집 가능 여부 |

### 3.4 FDetailsViewArgs — 디테일 뷰 생성 파라미터

| 파라미터 | 기본값 | 역할 |
|---------|--------|------|
| `bUpdatesFromSelection` | false | 에디터 선택과 자동 동기화 |
| `bLockable` | false | 잠금 버튼 표시 |
| `bAllowSearch` | true | 검색 바 표시 |
| `NameAreaSettings` | `ActorsUseNameArea` | 이름 영역 표시 조건 |

| `bForceHiddenPropertyVisibility` | false | CPF_Edit 없는 프로퍼티도 표시 |

## 4. 커스텀 디테일 패널 패턴 (IDetailCustomization)

### 시나리오 4: 커스텀 액터의 디테일 패널을 만들 때

```
[개발자] FMyActorDetails 클래스 작성 (IDetailCustomization 구현)
  │
  ▼
[모듈 코드] StartupModule()에서 등록
  │
  │  FPropertyEditorModule& PropModule =
  │      FModuleManager::LoadModuleChecked<FPropertyEditorModule>("PropertyEditor");
  │  PropModule.RegisterCustomClassLayout(
  │      "MyActor",                    ← 대상 클래스 이름
  │      FOnGetDetailCustomizationInstance::CreateStatic(&FMyActorDetails::MakeInstance)
  │  );                                ← 왜: 커스텀 인스턴스를 생성할 팩토리 델리게이트 등록
  │
  ├─ FCustomDetailLayoutNameMap에 {"MyActor" → Delegate} 추가
  │    ← 왜: 나중에 클래스 이름으로 빠르게 조회하기 위해 맵에 저장
  │
  ▼
[런타임] 사용자가 뷰포트에서 AMyActor를 클릭
  │
  ▼
[PropertyEditor] IDetailsView::SetObjects({MyActorInstance})
  │
  ▼
[PropertyEditor] FDetailLayoutBuilderImpl 생성
  │
  ├─ UObject::GetClass() → UClass("MyActor")
  │    ← 왜: 오브젝트의 실제 클래스를 확인
  │
  ├─ FCustomDetailLayoutNameMap에서 "MyActor" 검색
  │    ← 왜: 이 클래스에 등록된 커스텀 레이아웃이 있는지 확인
  │
  ├─ 매칭 발견 → FOnGetDetailCustomizationInstance 호출
  │    → FMyActorDetails::MakeInstance() 실행
  │    ← 왜: 커스텀 레이아웃 인스턴스를 새로 생성
  │
  ├─ 상속 체인도 검색 (MyActor → AActor → UObject)
  │    ← 왜: 부모 클래스의 커스터마이징도 적용 (예: AActor의 기본 디테일)
  │
  ▼
[PropertyEditor] FMyActorDetails::CustomizeDetails(IDetailLayoutBuilder&) 호출
  │  ← 왜: 개발자가 정의한 커스텀 UI 로직 실행
  │
  ├─ DetailBuilder.EditCategory("Combat")
  │    ← 왜: "Combat" 카테고리를 생성하거나 기존 카테고리 편집
  │
  ├─ DetailBuilder.GetProperty("Health") → IPropertyHandle
  │    ← 왜: Health 프로퍼티에 대한 핸들을 획득하여 커스텀 위젯 연결
  │
  ├─ DetailBuilder.HideProperty("InternalFlags")
  │    ← 왜: 사용자에게 불필요한 프로퍼티를 숨김
  │
  └─ Cat.AddCustomRow("HealthBar")
       .ValueContent()[ SNew(SProgressBar).Percent(HealthRatio) ]
       ← 왜: 기본 숫자 입력 대신 프로그레스 바로 Health 시각화
  │
  ▼
[PropertyEditor] GenerateDetailLayout() 계속
  │  ← 왜: 커스텀으로 처리되지 않은 나머지 프로퍼티는 기본 위젯으로 생성
  │
  ├─ 숨겨지지 않은 프로퍼티 → FDetailPropertyRow (기본 위젯)
  │
  └─ 커스텀 타입 레이아웃 검색 (FVector, FColor 등)
       ← 왜: 프로퍼티 타입별로도 위젯 커스터마이징이 적용될 수 있음
  │
  ▼
[디테일 패널] 최종 Slate 위젯 트리 완성 → 화면에 표시
```

### 4.1 클래스 커스터마이징 (IDetailCustomization)

**등록:**
```cpp
FPropertyEditorModule::RegisterCustomClassLayout(
    "MyActor",
    FOnGetDetailCustomizationInstance::CreateStatic(&FMyActorDetails::MakeInstance)
);
```

**구현:**
```cpp
class FMyActorDetails : public IDetailCustomization {
    void CustomizeDetails(IDetailLayoutBuilder& DetailBuilder) override {
        IDetailCategoryBuilder& Cat = DetailBuilder.EditCategory("MyCategory");
        Cat.AddCustomRow(LOCTEXT(...))
           .NameContent()[ SNew(STextBlock).Text(...) ]
           .ValueContent()[ SNew(SButton)... ];
    }
};
```

### 4.2 타입 커스터마이징 (IPropertyTypeCustomization)

**등록:**
```cpp
FPropertyEditorModule::RegisterCustomPropertyTypeLayout(
    "LinearColor",
    FOnGetPropertyTypeCustomizationInstance::CreateStatic(&FColorStructCustomization::MakeInstance)
);
```

**구현 인터페이스:**
```cpp
class IPropertyTypeCustomization {
    virtual void CustomizeHeader(TSharedRef<IPropertyHandle>, FDetailWidgetRow&,
                                 IPropertyTypeCustomizationUtils&) = 0;
    virtual void CustomizeChildren(TSharedRef<IPropertyHandle>, IDetailChildrenBuilder&,
                                   IPropertyTypeCustomizationUtils&) = 0;
};
```

### 4.3 IDetailLayoutBuilder 핵심 API

| 메서드 | 역할 |
|--------|------|
| `EditCategory(Name, DisplayName, Priority)` | 카테고리 생성/편집 |
| `GetProperty(Path, Class)` | 프로퍼티 핸들 획득 |
| `HideProperty(Handle)` | 특정 프로퍼티 숨기기 |
| `HideCategory(Name)` | 카테고리 전체 숨기기 |
| `GetBaseClass()` | 현재 커스터마이징 대상 클래스 |
| `GetObjectsBeingCustomized()` | 편집 중인 오브젝트 목록 |
| `ForceRefreshDetails()` | 강제 새로고침 |
| `SortCategories(Func)` | 카테고리 정렬 순서 재정의 |
| `AddObjectPropertyData()` | 외부 오브젝트 프로퍼티 추가 |
| `RegisterInstancedCustomPropertyTypeLayout()` | 인스턴스별 타입 커스텀 등록 |

**카테고리 우선순위 (`ECategoryPriority`):**
`Variable(0)` → `Transform` → `Important` → `TypeSpecific` → `Default` → `Uncommon`

### 4.4 DetailCustomizations 모듈의 등록 구조

`FDetailCustomizationsModule`은 `StartupModule()`에서 두 함수 호출:
- `RegisterObjectCustomizations()`: 클래스별 커스텀 (ActorDetails, CameraDetails 등 수십 개)
- `RegisterPropertyTypeCustomizations()`: 타입별 커스텀 (ColorStructCustomization, MathStructCustomizations 등)

등록된 이름을 `RegisteredClassNames` / `RegisteredPropertyTypes` `TSet`에 보관, `ShutdownModule()`에서 일괄 해제.

## 5. ImGui로 비슷한 기능을 구현할 때 참고할 구조

### 5.1 UE4 에디터 설계 핵심 — Retained Mode

| UE4 (Slate, Retained) | ImGui (Immediate) |
|----------------------|-------------------|
| `SWidget` 트리를 유지하고 변경 시 Invalidate | 매 프레임 UI 코드 재실행 |
| `IPropertyHandle`로 값 접근 추상화 | 직접 포인터/참조로 값 접근 |
| `FTabManager`로 탭 도킹/언도킹 관리 | 별도 도킹 시스템 필요 (ImGui 내장 or DockBuilder) |
| `IDetailCustomization`으로 타입별 UI 분리 | 타입별 함수 분기 또는 테이블 |

### 5.2 ImGui 에디터 구현 시 참고 구조

**1. 프로퍼티 에디터:**
- UE4의 `FProperty` 리플렉션 → 프레임워크에서는 자체 리플렉션 또는 메타데이터 시스템 필요
- `IPropertyHandle` 패턴 → ImGui에서는 `void* + 타입정보` 조합으로 범용 에디터 함수 구현
- 카테고리 시스템 → ImGui의 `CollapsingHeader` / `TreeNode`로 대응

**2. 커스텀 에디터 확장:**
- `RegisterCustomClassLayout` 패턴 → `std::unordered_map<TypeID, DrawFunction>` 테이블
- 타입별 위젯 분기: 기본 타입(int, float, string) → ImGui 내장, 커스텀 타입 → 등록된 함수 호출
- UE4의 `FDetailWidgetRow`(Name + Value 2열) → ImGui의 `Columns(2)` 또는 `Table`로 대응

**3. 콘텐츠 브라우저:**
- `FARFilter` (백엔드 필터) → 파일시스템 / 에셋 DB 쿼리
- `FFrontendFilter` (프론트엔드 필터) → ImGui InputText + 커스텀 필터 함수
- `EAssetViewType` 뷰 모드 → ImGui의 목록/그리드 레이아웃 분기

**4. 탭/패널 시스템:**
- `FTabManager` → ImGui DockSpace + DockBuilder API 활용
- `EToolkitTabSpot` → DockNode ID 매핑으로 영역 정의
- 독립 윈도우 (`Standalone`) → ImGui의 별도 OS 윈도우 또는 독립 뷰포트

### 5.3 최소 구현 권장 순서

1. **리플렉션/메타데이터 시스템** — 타입 정보로 프로퍼티 자동 열거
2. **범용 프로퍼티 에디터** — 타입별 ImGui 위젯 매핑 테이블
3. **커스텀 에디터 등록** — `RegisterCustomEditor(TypeID, DrawFunc)` 패턴
4. **카테고리 정리** — 프로퍼티 그룹핑 + CollapsingHeader
5. **에셋 브라우저** — 파일시스템 탐색 + 필터 + 썸네일
