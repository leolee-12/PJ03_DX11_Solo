# 작업 규칙

## 브랜치/저장소 규칙
- **현재 작업 브랜치 외 새 브랜치 생성 절대 금지**
- **origin/main 클론(checkout/merge) 절대 금지**
- main 코드 확인: `git show origin/main:경로` 사용 (fetch 선행)
- 작업 결과 md 파일은 origin/main에 PR로 통합 관리
- 브랜치 역할 구분:
  - `main`, `feature/*`: 코드 확인 전용 (읽기만)
  - `claude/*`: 문서/설정 작업 전용 (orphan 브랜치, 코드 파일 없음)

## 세션 자동 초기화 (SessionStart hook)
- `.claude/hooks/session-init.sh`가 자동 실행
- `BRANCH_MODE: inherit` → 이전 claude 브랜치 기반으로 생성
- `BRANCH_MODE: orphan` → 빈 브랜치로 새로 생성
- 수동 개입 없이 자동 진행 (사용자에게 브랜치명 묻지 않음)

## 작업 모드

### [분석] 모드
- **코드 수정 절대 금지**
- 분석 결과를 **마크다운(*.md) 파일로 작성**
- 문서는 `docs/analysis/` 폴더에 모델(Opus: O, Sonnet: S)과 넘버링 갱신하여 저장
  - 예: `docs/analysis/S01_ITEM_ANALYSIS.md`, `docs/analysis/O02_Item_System_Redesign.md`
- 간단한 요약이 필요한 경우만 루트에 저장 (50줄 이내)
- 작성 완료 후 세션 브랜치에 커밋/푸시

### [구현] 모드
- 실제 코드 작성 및 수정 (h, cpp 파일)
- 코드 수정은 별도 `feature/*` 브랜치에서 수행 (사용자 지시에 따라)
- 분석 문서는 claude 세션 브랜치에 커밋/푸시

## 할루시네이션 방지
- 클래스, 함수, 파일명을 언급할 때는 반드시 실제 소스코드에서 확인한 것만 기술
- 이론적인 내용은 추론하지 말고 신뢰할 수 있는 공식 문서를 웹에서 참조하여 답변
- 직접 확인하지 못한 내용은 "미확인" 또는 "추정"으로 명시
- 헤더만으로 파악 불가한 내용: "구현부 확인 필요"로 표시
- 사용자가 참고를 요청하지 않은 다른 엔진/프레임워크 버전의 내용을 현재 프로젝트에 섞지 않음

## .claude/ 문서 관리 규칙
- CONTEXT.md의 핵심 시스템 섹션이 길어지면 `.claude/systems/{시스템명}.md`로 분리
  - 예: `.claude/systems/rendering.md`, `.claude/systems/collision.md`
  - 분리 시 CONTEXT.md에는 파일 경로 참조만 남기고 상세 내용은 세부 문서로 이동
  - CLAUDE.md 문서 맵에도 해당 경로 추가

## PR 브랜치 작성 규칙
- **요청받은 변경사항만 포함** — 명시적으로 요청된 파일/변경만 PR에 넣을 것
- **다른 브랜치의 diff를 맹목적으로 적용 금지** — 옛 브랜치 diff에는 이미 main에 반영된 변경, 파일 이동/삭제, 프로젝트 구조 변경 등 의도하지 않은 내용이 섞여 있을 수 있음
- **사용자의 기존 작업(코드, 프로젝트, 파일)을 삭제/이동하지 않음** — 사용자가 명시적으로 지시한 경우에만 수행
- **PR 생성 전 `git diff --stat origin/main..HEAD`로 변경 목록을 반드시 검증** — 요청 범위를 벗어나는 변경이 있으면 제거 후 진행
- **파일 배치 위치가 불확실하면 사용자에게 확인** — 추측으로 폴더를 결정하지 않음

## 작업 완료 보고
- 작업 완료 후 반드시 멈추고 결과를 요약 보고
- 수행한 작업 내용 및 변경 사항
- 작업 중 불확실했거나 판단이 필요한 부분
- 결과물 저장 경로 (문서/코드)
