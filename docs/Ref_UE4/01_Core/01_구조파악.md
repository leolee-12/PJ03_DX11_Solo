# [1-1] UE4 Core 모듈 — 구조 파악

> 분석 대상: `Engine/Source/Runtime/Core/Public/` (.h 파일 928개)
> UE4 버전: 4.27

---

## 쉬운 개념 가이드

이 문서를 읽기 전에 알아두면 좋은 개념들:

**Core 모듈이란?**
- 게임 엔진의 "기초 공사"에 해당한다. 건물로 치면 철근, 시멘트, 배관 같은 것
- 게임의 캐릭터나 맵이 아니라, 메모리 관리/수학 계산/파일 저장 같은 **모든 게임이 공통으로 필요한 기능**을 모아둔 곳

**자주 나오는 용어 정리:**
| 용어 | 쉬운 설명 |
|------|----------|
| 할당자(Allocator) | 메모리를 빌려주고 돌려받는 관리자. "메모리 은행 창구 직원" |
| 컨테이너(Container) | 데이터를 담는 그릇. 배열=줄 세우기, 맵=사전, 셋=중복 없는 주머니 |
| 델리게이트(Delegate) | "나중에 이 함수를 대신 호출해줘"라고 맡기는 것. 전화번호부에 번호를 등록해두는 것과 비슷 |
| 스마트 포인터 | 메모리를 자동으로 정리해주는 똑똑한 포인터. "다 쓰면 알아서 반납하는 도서관 책" |
| 참조 카운팅 | "이 데이터를 몇 명이 쓰고 있나" 세는 것. 0명이 되면 삭제 |
| 해시(Hash) | 데이터를 숫자로 변환하는 것. "홍길동" → 12345. 빠른 검색에 사용 |
| 직렬화(Serialize) | 메모리의 데이터를 파일로 저장하거나 파일에서 불러오는 것 |
| SIMD | CPU가 한 번에 여러 숫자를 동시에 계산하는 기능. 계산기 4개를 동시에 누르는 것 |
| 인라인(Inline) | 함수를 호출하지 않고 코드를 직접 복붙하는 최적화 |

## 3. 영역별 클래스 계층 및 핵심 역할

### 3.1 메모리 관리 (HAL/, Templates/)

> 프로그램이 실행 중에 데이터를 저장할 공간(메모리)을 빌리고 돌려주는 시스템.
> `new`로 메모리를 빌리고, `delete`로 반납하는데, UE4는 이 과정을 직접 관리하는 "할당자"를 만들어 사용한다.

```
FUseSystemMallocForNew         ← 시스템 malloc을 사용하는 new/delete 오버로드
└── FMalloc                    ← 글로벌 메모리 할당자 인터페이스 (추상 클래스)
    ├── FMallocAnsi            ← 표준 C malloc 래퍼
    ├── FMallocBinned          ← 풀 기반 바이닝 할당자
    ├── FMallocBinned2         ← 개선된 바이닝 할당자 (기본)
    ├── FMallocBinned3         ← 차세대 바이닝 할당자
    ├── FMallocTBB             ← Intel TBB 할당자
    ├── FMallocMimalloc        ← mimalloc 기반 할당자
    ├── FMallocJemalloc        ← jemalloc 기반 할당자
    ├── FMallocDebug           ← 디버그용 할당자
    ├── FMallocStomp           ← 버퍼 오버런 감지용
    └── FMallocPoisonProxy     ← 프록시 패턴 할당자 래퍼
```

**스마트 포인터** (다 쓴 메모리를 자동으로 반납해주는 포인터들):

| 타입 | 역할 | 비유 |
|------|------|------|
| `TSharedRef<T>` | 여러 명이 공유, 반드시 유효 (null 불가) | 공동 소유 자전거 — 항상 존재 |
| `TSharedPtr<T>` | 여러 명이 공유, 비어있을 수 있음 | 공동 소유 자전거 — 없을 수도 있음 |
| `TWeakPtr<T>` | "빌려 보기만" — 소유권 없음 | 자전거 주차된 곳만 알고 있음, 누가 치웠을 수도 |
| `TUniquePtr<T>` | 딱 1명만 소유, 양도만 가능 | 내 전용 자전거 — 빌려줄 순 있지만 공유 안 됨 |

**참조 카운팅 베이스** ("지금 이 데이터를 몇 명이 쓰고 있나?" 세는 기반 클래스):

```
IRefCountedObject              ← 참조 카운팅 인터페이스 (규격만 정의)
FRefCountBase                  ← 멀티스레드에서도 안전한 카운팅 (Atomic 연산)
FRefCountedObject              ← 단일 스레드용 카운팅 (구버전)
```

### 3.2 컨테이너 (Containers/)

> 데이터를 저장하고 검색하는 "그릇"들. 용도에 따라 다른 그릇을 쓴다.

```
[핵심 4종]
TArray<T>                      ← 동적 배열 — 순서대로 나열 (학생 번호순 명단)
TMap<K,V>                      ← 해시맵 — 이름으로 검색 (전화번호부: 이름→번호)
TSet<T>                        ← 해시셋 — 중복 없는 모음 (출석부: 있다/없다)
FString                        ← 동적 문자열 — 글자를 담는 배열

TIndirectArray<T>              ← 포인터 배열 (요소를 힙에 개별 할당)
TSortedMap<K,V>                ← 정렬된 맵
TStaticArray<T,N>              ← 고정 크기 배열
TBitArray                      ← 비트 배열
TSparseArray<T>                ← 희소 배열 (빈 슬롯 재사용)
TChunkedArray<T>               ← 청크 기반 배열
TQueue<T>                      ← SPSC/MPSC 큐
TCircularBuffer<T>             ← 원형 버퍼
TCircularQueue<T>              ← 원형 큐
TLockFreeList<T>               ← Lock-Free 연결 리스트
TDoubleLinkedList<T>           ← 이중 연결 리스트 (List.h)
TLruCache<K,V>                 ← LRU 캐시
```

### 3.3 델리게이트 시스템 (Delegates/)

> **델리게이트** = "이벤트가 발생하면 이 함수를 호출해줘"라고 등록하는 시스템.
> 예: "적이 죽으면 점수 올려줘", "버튼을 누르면 문 열어줘" → 이런 연결을 만드는 것.

```
FDelegateHandle                ← 등록된 함수를 식별하는 번호표
IDelegateInstance              ← 등록된 함수 하나를 감싸는 인터페이스
FDelegateBase                  ← 함수 1개만 등록 가능한 기본형
TMulticastDelegateBase<>       ← 함수 여러 개를 등록하고 한 번에 호출하는 확장형
```

**델리게이트 종류:**

| 매크로 | 설명 | 비유 |
|--------|------|------|
| `DECLARE_DELEGATE` | 함수 1개만 연결 | 전화 1개만 받는 직통 전화 |
| `DECLARE_MULTICAST_DELEGATE` | 함수 여러 개 연결, `Broadcast()`로 전부 호출 | 단체 문자 — 등록된 사람 모두에게 전송 |
| `DECLARE_DYNAMIC_DELEGATE` | 블루프린트에서도 사용 가능한 버전 | 프로그래머가 아닌 사람도 쓸 수 있는 버전 |

**바인딩 방식** (어떤 종류의 함수를 연결할 수 있나): BindRaw(일반 포인터), BindSP(스마트 포인터), BindStatic(전역 함수), BindLambda(익명 함수) 등

### 3.4 문자열 처리

> UE4는 용도에 따라 3가지 문자열 타입을 구분한다.

| 타입 | 용도 | 비유 |
|------|------|------|
| `FString` | 자유롭게 수정 가능한 문자열 (연결, 자르기, 포맷) | 연필로 쓴 메모 — 마음대로 수정 |
| `FName` | 변경 불가 식별자, 비교가 매우 빠름 (숫자 비교) | 주민등록번호 — 한 번 정해지면 고정, 비교는 번호만 |
| `FText` | 화면에 보여주는 텍스트, 다국어 지원 | 게임 UI에 표시되는 번역 가능한 텍스트 |

**FName이 빠른 이유:**
- 처음 "Weapon"이라는 문자열이 등장하면 전역 테이블에 등록하고 고유 번호(인덱스)를 받음
- 이후에는 문자열을 비교하지 않고 **번호만 비교** → 숫자 비교 한 번 = O(1)
- `NAME_SIZE = 1024` (이름 최대 길이)
- `FNameEntryId` — 내부적으로 `uint32` 정수 하나

### 3.5 수학 라이브러리 (Math/)

```
기본 타입:
├── FVector        ← 3D 벡터 (float X, Y, Z)
├── FVector2D      ← 2D 벡터 (float X, Y)
├── FVector4       ← 4D 벡터
├── FIntPoint      ← 정수 2D 좌표
├── FIntVector     ← 정수 3D 벡터
├── FPlane         ← 평면 (FVector 상속 + W)
├── FMatrix        ← 4×4 행렬 (float M[4][4], 16바이트 정렬)
├── FQuat          ← 쿼터니언 (float X, Y, Z, W, 16바이트 정렬)
├── FRotator       ← 오일러 회전 (float Pitch, Yaw, Roll — 도 단위)
└── FTransform     ← 위치 + 회전 + 스케일 (FQuat + FVector + FVector)

색상:
├── FLinearColor   ← 리니어 색상 (float R, G, B, A)
└── FColor         ← 8비트 색상 (uint8 B, G, R, A — BGRA 순서)

바운딩:
├── FBox           ← AABB (Min, Max FVector)
├── FBox2D         ← 2D AABB
├── FSphere        ← 구 (Center + Radius)
├── FBoxSphereBounds ← AABB + 바운딩 구
└── FOrientedBox   ← OBB

행렬 팩토리:
├── FRotationMatrix, FRotationTranslationMatrix
├── FScaleMatrix, FScaleRotationTranslationMatrix
├── FTranslationMatrix
├── FPerspectiveMatrix, FOrthoMatrix
├── FMirrorMatrix, FClipProjectionMatrix
└── FQuatRotationTranslationMatrix

유틸리티:
├── FMath (FGenericPlatformMath)  ← 수학 유틸리티 함수 집합
├── FRandomStream               ← 결정적 난수 생성기
├── TRange<T>, TRangeBound<T>   ← 범위 타입
├── FInterpCurve<T>             ← 보간 커브
└── FFloat16                    ← 16비트 부동소수점
```

**FVector 정적 상수:** ZeroVector, OneVector, UpVector(0,0,1), ForwardVector(1,0,0), RightVector(0,1,0)

**FMatrix 주의사항:**
- `Res = Mat1 * Mat2`는 실제로 `Mat2^T * Mat1` (전치 사전 곱셈)
- 원소 접근: `M[RowIndex][ColumnIndex]`

**FTransform:** 벡터화/비벡터화 구현 분리 (TransformVectorized.h / TransformNonVectorized.h)

**SIMD 지원:** UnrealMathSSE.h, UnrealMathNeon.h, UnrealMathFPU.h, VectorRegister

### 3.6 멀티스레딩 (HAL/, Async/)

> **스레드** = 프로그램 안에서 동시에 여러 작업을 하는 것. 요리사 1명이 모든 요리를 순서대로 하면 느리지만,
> 요리사 여러 명(스레드)이 동시에 각자 다른 요리를 하면 빠르다.

```
FRunnable                      ← 스레드에서 실행 가능한 객체 인터페이스
                                  Init() → Run() → Exit(), Stop()으로 중단

FRunnableThread                ← 스레드 래퍼, static Create() 패턴
                                  SetThreadPriority, Suspend, Kill, WaitForCompletion

FThread (HAL/Thread.h)         ← C++11 std::thread 스타일 래퍼

FThreadManager                 ← 전체 스레드 관리
FThreadSafeCounter             ← 원자적 카운터
FThreadSafeBool                ← 원자적 bool
FCriticalSection               ← 뮤텍스 래퍼
FEvent                         ← 이벤트 동기화 객체

TaskGraph 시스템:
├── ENamedThreads::Type        ← 명명 스레드 (GameThread, RenderThread, RHIThread 등)
├── FBaseGraphTask             ← TaskGraph 태스크 기반 클래스
├── FGraphEvent                ← 태스크 완료 이벤트
└── DECLARE_CYCLE_STAT 관련    ← 태스크별 프로파일링 통계

비동기 작업:
├── FAutoDeleteAsyncTask<T>    ← 완료 후 자동 삭제 비동기 태스크
├── FAsyncTask<T>              ← 수동 관리 비동기 태스크
├── FNonAbandonableTask        ← 포기 불가 태스크 기반
├── TFuture<T>                 ← 비동기 결과 (Promise/Future 패턴)
└── ParallelFor()              ← 병렬 for 루프
```

**ENamedThreads 주요 스레드:**

| 스레드 | 역할 |
|--------|------|
| GameThread | 게임 로직 메인 스레드 |
| ActualRenderingThread | 실제 렌더링 스레드 |
| RHIThread | RHI 커맨드 실행 스레드 |
| AudioThread | 오디오 처리 스레드 |
| AnyThread | 워커 스레드 풀 (우선순위별 Normal/High/Background) |

## 4. 핵심 매크로 및 타입 별칭

### 매크로

| 매크로 | 위치 | 역할 |
|--------|------|------|
| `CORE_API` | 전역 | DLL export/import |
| `FORCEINLINE` | 전역 | 강제 인라인 |
| `MS_ALIGN(N)` / `GCC_ALIGN(N)` | 전역 | 메모리 정렬 |

## 7. Serialization — FArchive 상속 계층

> **직렬화(Serialization)란?** 메모리에 있는 데이터를 파일로 저장하거나, 파일에서 메모리로 불러오는 것.
> 게임 세이브/로드가 대표적인 예. FArchive는 `<<` 연산자 하나로 저장/로드를 동일한 코드로 처리한다.
> 예: `Archive << MyHP;` → 저장 모드면 파일에 쓰고, 로드 모드면 파일에서 읽는다.

### 7.1 FArchive 핵심 인터페이스

```
FArchiveState (private 상속)
└── FArchive                     ← 직렬화 기반 클래스
    ├── Serialize(void*, int64)  ← 원시 바이트 직렬화 (핵심 가상 함수)
    ├── operator<< (FName, FText, UObject*, 기본 타입들)
    ├── Tell(), Seek(), TotalSize()
    ├── IsLoading() / IsSaving()  ← 방향 판정
    ├── SetError(), IsError()
    └── CustomVer(), GetCustomVersions()  ← 버전 관리
```

### 7.2 상속 계층도

```
FArchive
├── FMemoryArchive               ← 메모리 기반 직렬화 (Seek/Tell 구현)
│   ├── FMemoryReader            ← TArray<uint8>에서 읽기
│   ├── FMemoryWriter            ← TArray<uint8>에 쓰기
│   │   └── FBufferArchive       ← FMemoryWriter + TArray<uint8> (자체 버퍼 보유)
│   ├── FLargeMemoryReader       ← 대용량(>2GB) 메모리 읽기
│   ├── FLargeMemoryWriter       ← 대용량(>2GB) 메모리 쓰기
│   └── FArrayReader             ← FMemoryArchive + TArray<uint8> (자체 버퍼 보유)
│
├── FArchiveProxy                ← 프록시 패턴 기반 (InnerArchive 위임)
│   ├── FNameAsStringProxyArchive
│   └── FNameAsStringIndexProxyArchive
│
├── FBufferReaderBase            ← 원시 포인터 기반 버퍼 읽기 (void* Data)
│   └── FBufferReader            ← SHA 검증 옵션 포함
│
├── FBitArchive                  ← 비트 단위 직렬화 기반 (네트워크)
│   ├── FBitReader               ← 비트스트림 읽기
│   └── FBitWriter               ← 비트스트림 쓰기
│
├── FArchiveLoadCompressedProxy  ← 압축 데이터 투명 읽기
├── FArchiveSaveCompressedProxy  ← 압축 데이터 투명 쓰기
│
└── FStructuredArchive           ← 구조화 직렬화 (Record/Array/Stream/Map)
    └── FArchiveProxy 기반, Formatter 패턴 사용
```

### 7.3 핵심 파생 클래스 요약

| 클래스 | 용도 | 특징 |
|--------|------|------|
| `FMemoryReader` | 메모리→객체 역직렬화 | TArray<uint8> 참조, SetIsLoading(true) |
| `FMemoryWriter` | 객체→메모리 직렬화 | TArray<uint8> 참조, 2GB 제한 |
| `FBufferArchive` | 자체 버퍼 쓰기 | FMemoryWriter+TArray 다중 상속 |
| `FLargeMemoryReader/Writer` | 2GB 초과 데이터 | int64 기반 |
| `FArchiveProxy` | 동작 수정 프록시 | InnerArchive에 위임 |
| `FBitReader/Writer` | 네트워크 비트스트림 | SerializeBits, 비트 단위 제어 |
| `FStructuredArchive` | JSON/텍스트 포맷 지원 | Record→Field→Value 구조 |

### 8.3 로그 카테고리 구조

```
FLogCategoryBase                 ← 로그 카테고리 기반 클래스
├── CategoryName (FName)          ← 카테고리 이름
├── Verbosity                     ← 현재 런타임 verbosity
├── DefaultVerbosity              ← 기본 verbosity
├── CompileTimeVerbosity          ← 컴파일 타임 최대 verbosity
└── IsSuppressed(Level) → bool    ← 로그 출력 억제 판정

FLogCategory<Default, CompileTime>  ← 템플릿 파생 (컴파일 타임 상수 전달)
```

**카테고리 선언/정의 매크로:**

| 매크로 | 용도 |
|--------|------|
| `DECLARE_LOG_CATEGORY_EXTERN(Name, Default, CompileTime)` | 헤더에 extern 선언 |
| `DEFINE_LOG_CATEGORY(Name)` | cpp에 정의 |
| `DEFINE_LOG_CATEGORY_STATIC(Name, Default, CompileTime)` | 파일 로컬 정의 |
| `DECLARE_LOG_CATEGORY_CLASS(Name, Default, CompileTime)` | 클래스 내 선언 |

**UE_LOG 매크로 동작 흐름:**

```
UE_LOG(CategoryName, Verbosity, Format, ...)
  → 컴파일 타임 verbosity 체크 (TEnableIf)
  → 런타임 IsSuppressed() 체크
  → FMsg::Logf_Internal() 호출
  → GLog(FOutputDeviceRedirector)로 전달
  → 등록된 모든 FOutputDevice에 Serialize()
```

```
├── TearDown()                   ← 싱글톤 파괴
│
├── 모듈 로드/언로드:
│   ├── LoadModule(Name) → IModuleInterface*
│   ├── LoadModuleChecked(Name) → IModuleInterface&   (실패시 assert)
│   ├── LoadModuleWithFailureReason(Name, OutResult)
│   ├── UnloadModule(Name, bIsShutdown)
│   └── UnloadModulesAtShutdown()     ← 역순 언로드
│
├── 모듈 조회:
│   ├── GetModule(Name) → IModuleInterface*
│   ├── GetModuleChecked<T>(Name) → T&   (타입 캐스트 + assert)
│   ├── GetModulePtr<T>(Name) → T*       (타입 캐스트, null 가능)
│   ├── IsModuleLoaded(Name) → bool       (O(1))
│   └── ModuleExists(Name) → bool
│
├── 정적 링크 모듈:
│   ├── RegisterStaticallyLinkedModule(Name, Delegate)
│   └── FInitializeStaticallyLinkedModule  ← 모듈 생성 델리게이트
│
├── 이벤트:
│   ├── OnModulesChanged()  → FModulesChangedEvent (모듈 로드/언로드 통지)
│   └── OnProcessLoadedObjectsCallback()  ← UObject 처리 콜백
│
└── 내부:
    ├── FModuleInfo               ← 모듈 정보 (Handle, Module, LoadOrder 등)
    ├── FModuleMap (TMap<FName, ModuleInfoRef>)
    └── LoadOrder 기반 역순 셧다운
```

### 9.3 모듈 로드/언로드 흐름

```
로드: FModuleManager::LoadModule(Name)
  → DLL 로드 (또는 정적 링크 초기화 델리게이트 실행)
  → IModuleInterface 인스턴스 생성
  → StartupModule() 호출
  → OnModulesChanged(Name, ModuleLoaded) 브로드캐스트
  → LoadOrder 기록

셧다운: UnloadModulesAtShutdown()
  → LoadOrder 역순으로 정렬
  → 각 모듈에 대해:
    → ShutdownModule() 호출
    → 모듈 인스턴스 파괴
    → DLL 언로드
```

### 9.4 EModuleLoadResult

| 값 | 설명 |
|----|------|
| `Success` | 정상 로드 |
| `FileNotFound` | 모듈 파일 없음 |
| `FileIncompatible` | 호환 불가 |
| `CouldNotBeLoadedByOS` | OS 레벨 DLL 로드 실패 |
| `FailedToInitialize` | 초기화 실패 |
