## 쉬운 개념 가이드

**3D 게임에 수학이 필요한 이유:**
- 캐릭터 위치(어디에 있나?) → **벡터** (x, y, z 좌표)
- 카메라 회전(어디를 보나?) → **행렬** 또는 **쿼터니언** (회전 표현)
- 3D → 2D 화면 변환 → **투영 행렬** (3D 세계를 모니터에 그리기)

| 용어 | 쉬운 설명 |
|------|----------|
| 벡터(Vector) | 방향과 크기를 가진 화살표. 게임에서는 주로 "위치"나 "방향"을 나타냄 |
| 행렬(Matrix) | 숫자를 4×4 격자로 배열한 것. 이동/회전/크기변환을 한 번에 표현 |
| 쿼터니언(Quaternion) | 회전을 4개 숫자로 표현한 것. 행렬보다 가볍고 짐벌락 문제 없음 |
| 투영(Projection) | 3D 세계를 2D 화면에 옮기는 것. 사진 찍는 것과 비슷 |
| SIMD | CPU가 한 번에 4개 숫자를 동시 계산하는 기능. 4배 빠른 계산기 |
| Row-Major | 행렬을 메모리에 저장할 때 행(가로줄) 단위로 저장하는 방식 |
| Reversed-Z | 가까운 물체=1, 먼 물체=0으로 깊이를 저장. 정밀도가 카메라 근처에서 높아짐 |

## 1. 좌표계 컨벤션

### UE4의 축 방향 (왼손 좌표계)

```
       Z (위)
       |
       |   X (앞)
       |  /
       | /
       +------→ Y (오른쪽)
```

**소스코드에서 확인한 상수:**
```cpp
FVector::ForwardVector(1, 0, 0);   // X = 앞
FVector::RightVector(0, 1, 0);     // Y = 오른쪽
FVector::UpVector(0, 0, 1);        // Z = 위
```

### DX11 프레임워크 시 주의사항
- UE4는 **왼손 좌표계 + Z-Up**
- D3D 기본값은 **왼손 좌표계 + Y-Up**
- 프로젝트에 맞게 선택. UE4 방식(Z-Up)을 쓸 수도 있고, D3D 기본(Y-Up)을 쓸 수도 있음

## 2. FMatrix — 행렬

### 메모리 구조

```cpp
MS_ALIGN(16) struct FMatrix {      // 16바이트 정렬 (SIMD 연산에 필요)
    float M[4][4];                  // 4×4 = 16개 float
    // M[행][열] — 행 우선(Row-Major) 저장
};
```

> **행 우선(Row-Major)이란?**
> 행렬을 메모리에 저장할 때, 가로줄(행)을 연속으로 저장하는 것.
> `[행0의 4개 값][행1의 4개 값][행2의 4개 값][행3의 4개 값]`

### 행렬 곱셈 규약

UE4는 **행 벡터 × 행렬** 규약 (v * M):
```
결과 = [x, y, z, 1] × Matrix
```

> **왜 이게 중요한가?** HLSL(셰이더 언어)에서 `mul(v, M)` 호출 시 동일한 결과를 얻으려면
> C++ 측 행렬을 그대로 전달할 수 있다. 만약 반대 규약이면 전치(행↔열 교환)가 필요.

### SSE 최적화 (행렬 곱셈)

> 4×4 행렬 곱셈은 64번의 곱셈 + 48번의 덧셈이 필요.
> SSE를 쓰면 4개 float를 한 번에 처리하여 약 4배 빠르게 계산.

핵심 패턴:
1. 행의 한 성분을 4개로 복제 (broadcast): `{x,x,x,x}`
2. 상대 행렬의 행과 곱하기: `{x,x,x,x} × {a,b,c,d}`
3. 4번 반복하여 결과 한 행 완성

## 3. 투영 행렬

### 원근 투영 (FPerspectiveMatrix) — 일반적인 3D 게임 카메라

> 멀리 있는 물체는 작게, 가까운 물체는 크게 보이게 만드는 행렬.
> 사진을 찍으면 멀리 있는 건물이 작게 나오는 것과 같은 원리.

```
행렬 구조 (행 우선):
  행0: [X 스케일, 0,         0,                    0]  ← FOV에 따른 X 축소
  행1: [0,        Y 스케일,  0,                    0]  ← FOV에 따른 Y 축소
  행2: [0,        0,         깊이 매핑,             1]  ← Z → 깊이값 변환 + 원근 플래그
  행3: [0,        0,         깊이 오프셋,           0]  ← near×far 관련 보정값
```

**원근 나눗셈**: 결과의 W 성분이 원래 Z값이 됨 → GPU가 x/w, y/w로 나누면 원근감 발생

### Reversed-Z (UE4 기본) ★중요★

> **일반**: 가까운 물체=0, 먼 물체=1로 깊이 저장
> **Reversed-Z**: 가까운 물체=1, 먼 물체=0으로 깊이 저장

**왜?** float는 0에 가까울수록 정밀도가 높다. 일반 방식이면 먼 곳의 정밀도가 높고 가까운 곳은 낮아진다.
게임에서는 **가까운 곳의 정밀도가 더 중요** (캐릭터 앞의 물체가 겹치지 않아야 하므로).
Reversed-Z로 뒤집으면 가까운 곳에 더 많은 정밀도가 배분된다.

### 직교 투영 (FOrthoMatrix) — 원근감 없는 카메라

> 멀리 있어도 크기가 같게 보이는 투영. 미니맵, UI, 2D 게임, 에디터 뷰 등에 사용.

## 4. FTransform — 위치 + 회전 + 크기

> 게임 오브젝트의 "어디에, 어느 방향으로, 얼마나 크게" 있는지를 하나로 묶은 구조체.

### 벡터화 vs 비벡터화 분기

```
[컴파일 타임 분기]
ENABLE_VECTORIZED_TRANSFORM (= PLATFORM_ENABLE_VECTORINTRINSICS)
  → 1: TransformVectorized.h     ← __m128 사용, SIMD 연산
  → 0: TransformNonVectorized.h  ← 일반 float 연산
```

### 벡터화 버전 (SSE 사용 — 대부분의 PC)

```cpp
MS_ALIGN(16) struct FTransform {
    VectorRegister Rotation;      // 쿼터니언 (__m128 = 4 float)
    VectorRegister Translation;   // 위치 (__m128, W=0)
    VectorRegister Scale3D;       // 크기 (__m128, W=0)
};
// sizeof = 48바이트 (16 × 3)
```

### 비벡터화 버전 (SSE 미지원 플랫폼)

```cpp
struct FTransform {
    FQuat   Rotation;      // 16바이트
    FVector Translation;   // 12바이트
    FVector Scale3D;       // 12바이트
};
// sizeof = 40바이트 (패딩 포함)
```

## 5. SIMD 플랫폼 추상화

> SIMD = CPU가 한 번에 4개 float를 동시에 처리하는 기능.
> 벡터/행렬 계산에서 약 4배 성능 향상.

### 플랫폼별 구현 선택 (VectorRegister.h)

```
VectorRegister.h (공통 인터페이스)
├── x86 PC      → UnrealMathSSE.h   (__m128, SSE 명령어)
├── ARM 모바일  → UnrealMathNeon.h  (float32x4_t, NEON 명령어)
└── 기타        → UnrealMathFPU.h   (일반 float, 느리지만 어디서든 동작)
```

### 주요 SIMD 함수

| 함수 | 기능 | 비유 |
|------|------|------|
| `VectorMultiply(A, B)` | {a1×b1, a2×b2, a3×b3, a4×b4} | 4개 곱셈 동시 |
| `VectorMultiplyAdd(A, B, C)` | A×B + C (한 번에) | 곱하고 더하기 동시 |
| `VectorReplicate(V, 2)` | {v2, v2, v2, v2} | 하나를 4개로 복제 |
| `VectorMatrixMultiply` | 4×4 행렬 곱 | 위 함수들 조합 |

### 프레임워크 적용 전략
- DX11 전용이므로 **DirectXMath** 사용 권장 (SSE2 기본 활용)
- DirectXMath의 `XMVECTOR` = UE4의 `VectorRegister` = `__m128`
- UE4처럼 자체 래퍼를 만들 필요 없이 DirectXMath API를 직접 사용

## 6. 종합 — DX11 프레임워크 권장사항

| 결정 사항 | 권장 | 근거 |
|-----------|------|------|
| 좌표계 | 왼손 | D3D 기본, UE4 동일 |
| 행렬 저장 | Row-Major | UE4 동일, HLSL `row_major` 호환 |
| 벡터 규약 | 행 벡터 (v × M) | HLSL `mul(v, M)` 호환 |
| 깊이 매핑 | **Reversed-Z [1→0]** | 부동소수점 정밀도 극대화 |
| 깊이 포맷 | D32_FLOAT | Reversed-Z와 최적 조합 |
| 깊이 비교 | GREATER_EQUAL | Reversed-Z에서 near=1, far=0 |
| SIMD | DirectXMath | DX11 전용, SSE2 기본, 래퍼 불필요 |
