## 1. FDynamicRHI → D3D11 구현 매핑 (4개 예시)

### 상속 관계

```
FDynamicRHI (순수 가상 인터페이스)
    └── FD3D11DynamicRHI : public FDynamicRHI, public IRHICommandContextPSOFallback
```

`FD3D11DynamicRHI`는 **리소스 팩토리(FDynamicRHI)**와 **커맨드 컨텍스트(IRHICommandContextPSOFallback)**를 동시에 구현하는 다중 상속 구조이다. D3D11은 디바이스 컨텍스트가 하나이므로 두 역할을 한 클래스에 합쳤다.

### 예시 1: 렌더 상태 (SamplerState)

| RHI 추상 | D3D11 구현 |
|----------|-----------|
| `FDynamicRHI::RHICreateSamplerState()` | `FD3D11DynamicRHI::RHICreateSamplerState()` |
| `FSamplerStateInitializerRHI` (필터, 주소 모드 등) | → `D3D11_SAMPLER_DESC` 변환 |
| 반환: `FRHISamplerState` | 반환: `FD3D11SamplerState` (= FRHISamplerState + `TRefCountPtr<ID3D11SamplerState> Resource`) |
| D3D11 API 호출 | `ID3D11Device::CreateSamplerState()` |

**래핑 구조**: `FD3D11SamplerState : FRHISamplerState` → 내부에 `ID3D11SamplerState` COM 포인터 보유

### 예시 2: 셰이더 (VertexShader)

| RHI 추상 | D3D11 구현 |
|----------|-----------|
| `FDynamicRHI::RHICreateVertexShader(Code, Hash)` | `FD3D11DynamicRHI::RHICreateVertexShader()` |
| 입력: `TArrayView<const uint8> Code` | 바이트코드에서 ShaderResourceTable 추출 후 |
| 반환: `FRHIVertexShader` | 반환: `FD3D11VertexShader` |
| D3D11 API 호출 | `ID3D11Device::CreateVertexShader()` |

**래핑 구조**: `FD3D11VertexShader : FRHIVertexShader, FD3D11ShaderData` → 다중 상속
- `FD3D11ShaderData`: ShaderResourceTable, UniformBuffers, StaticSlots, UAVMask 등 메타데이터
- `TRefCountPtr<ID3D11VertexShader> Resource`: COM 셰이더 오브젝트
- `TArray<uint8> Code`: InputLayout 생성에 필요한 바이트코드 보존 (VS만)

### 예시 3: 버퍼 (VertexBuffer)

| RHI 추상 | D3D11 구현 |
|----------|-----------|
| `FDynamicRHI::RHICreateVertexBuffer(Size, Usage, ...)` | `FD3D11DynamicRHI::RHICreateVertexBuffer()` |
| 반환: `FRHIVertexBuffer` | 반환: `FD3D11VertexBuffer` |
| D3D11 API 호출 | `ID3D11Device::CreateBuffer()` (D3D11_BIND_VERTEX_BUFFER) |

**래핑 구조**: `FD3D11VertexBuffer : FRHIVertexBuffer, FD3D11BaseShaderResource`
- `TRefCountPtr<ID3D11Buffer> Resource`
- `FD3D11BaseShaderResource`: SRV 바인딩 추적에 사용 (상태 캐시 무효화 시 필요)

### 예시 4: Draw Call (DrawIndexedPrimitive)

| RHI 추상 | D3D11 구현 |
|----------|-----------|
| `IRHICommandContext::RHIDrawIndexedPrimitive()` | `FD3D11DynamicRHI::RHIDrawIndexedPrimitive()` |
| 파라미터: IndexBuffer, BaseVertex, NumPrimitives 등 | D3D11 파라미터로 변환 |
| D3D11 API 호출 | `ID3D11DeviceContext::DrawIndexed()` |

커맨드 컨텍스트와 팩토리가 동일 클래스(`FD3D11DynamicRHI`)에서 구현됨.

## 2. RHI 리소스 ↔ D3D11 리소스 래핑 구조

### 래핑 패턴: "다중 상속 + COM TRefCountPtr"

모든 D3D11 리소스 클래스는 다음 패턴을 따른다:

```cpp
class FD3D11XXX : public FRHIXXX [, public FD3D11BaseShaderResource] {
    TRefCountPtr<ID3D11YYY> Resource;  // D3D11 COM 오브젝트
};
```

### 전체 매핑 테이블

| RHI 추상 클래스 | D3D11 구현 클래스 | D3D11 COM 오브젝트 |
|----------------|------------------|-------------------|
| **State** | | |
| `FRHISamplerState` | `FD3D11SamplerState` | `ID3D11SamplerState` |
| `FRHIRasterizerState` | `FD3D11RasterizerState` | `ID3D11RasterizerState` |
| `FRHIDepthStencilState` | `FD3D11DepthStencilState` | `ID3D11DepthStencilState` |
| `FRHIBlendState` | `FD3D11BlendState` | `ID3D11BlendState` |
| **Shader** | | |
| `FRHIVertexShader` | `FD3D11VertexShader` | `ID3D11VertexShader` + Code[] |
| `FRHIPixelShader` | `FD3D11PixelShader` | `ID3D11PixelShader` |
| `FRHIHullShader` | `FD3D11HullShader` | `ID3D11HullShader` |
| `FRHIDomainShader` | `FD3D11DomainShader` | `ID3D11DomainShader` |
| `FRHIGeometryShader` | `FD3D11GeometryShader` | `ID3D11GeometryShader` |
| `FRHIComputeShader` | `FD3D11ComputeShader` | `ID3D11ComputeShader` |
| **Buffer** | | |
| `FRHIVertexBuffer` | `FD3D11VertexBuffer` | `ID3D11Buffer` |
| `FRHIIndexBuffer` | `FD3D11IndexBuffer` | `ID3D11Buffer` |
| `FRHIStructuredBuffer` | `FD3D11StructuredBuffer` | `ID3D11Buffer` |
| `FRHIUniformBuffer` | `FD3D11UniformBuffer` | `ID3D11Buffer` + ResourceTable |
| **Texture** | | |
| `FRHITexture2D` | `TD3D11Texture2D<FD3D11BaseTexture2D>` | `ID3D11Texture2D` |
| `FRHITexture2DArray` | `TD3D11Texture2D<FD3D11BaseTexture2DArray>` | `ID3D11Texture2D` |
| `FRHITexture3D` | `FD3D11Texture3D` | `ID3D11Texture3D` |
| `FRHITextureCube` | `TD3D11Texture2D<FD3D11BaseTextureCube>` | `ID3D11Texture2D` |
| **View** | | |
| `FRHIShaderResourceView` | `FD3D11ShaderResourceView` | `ID3D11ShaderResourceView` |
| `FRHIUnorderedAccessView` | `FD3D11UnorderedAccessView` | `ID3D11UnorderedAccessView` |

### 텍스처 래핑의 특이점

텍스처는 **템플릿 + 다중 상속** 구조가 특히 복잡하다:

```
TD3D11Texture2D<BaseResourceType> : BaseResourceType, FD3D11TextureBase
    BaseResourceType = FRHITexture2D | FRHITexture2DArray | FRHITextureCube

FD3D11TextureBase (D3D11 전용 기반 클래스)
    ├── ID3D11Resource* Resource              (D3D11 텍스처)
    ├── ID3D11ShaderResourceView* ShaderResourceView  (기본 SRV)
    ├── TArray<ID3D11RenderTargetView*> RenderTargetViews (Mip별 RTV)
    ├── ID3D11DepthStencilView* DepthStencilViews[4]  (접근 모드별 DSV)
    └── FD3D11BaseShaderResource* BaseShaderResource   (상태 캐시 추적용)
```

핵심: 하나의 텍스처 객체가 **리소스 + SRV + RTV + DSV**를 모두 보유한다. 생성 시 Flags에 따라 필요한 뷰들이 함께 생성된다.

### ResourceCast 패턴

RHI 추상 타입 → D3D11 구체 타입 변환은 `static_cast` + 트레이트 클래스로 처리:

```cpp
template<typename TRHIType>
static FORCEINLINE typename TD3D11ResourceTraits<TRHIType>::TConcreteType* ResourceCast(TRHIType* Resource)
{
    return static_cast<typename TD3D11ResourceTraits<TRHIType>::TConcreteType*>(Resource);
}
// 사용: FD3D11VertexBuffer* D3DBuf = ResourceCast(VertexBufferRHI);
```

## 3. RHICreateTexture2D() 전체 호출 체인

```
[게임/렌더 코드]
    │
    ▼
(1) ::RHICreateTexture2D(SizeX, SizeY, Format, NumMips, NumSamples, Flags, ResourceState, CreateInfo)
    │  ← 전역 인라인 함수 (RHICommandList.h:5336)
    │
    ▼
(2) GDynamicRHI->RHICreateTexture2D_RenderThread(ImmediateCommandList, ...)
    │  ← FDynamicRHI 가상 함수 호출 (GDynamicRHI 전역 포인터 경유)
    │
    ▼
(3) FD3D11DynamicRHI::RHICreateTexture2D_RenderThread(RHICmdList, ...)
    │  ← D3D11 구현 (D3D11Texture.cpp:1226)
    │  → D3D11에서는 RHICmdList 무시, 직접 호출로 포워딩
    │
    ▼
(4) FD3D11DynamicRHI::RHICreateTexture2D(SizeX, SizeY, ...)
    │  ← D3D11Texture.cpp:1221
    │
    ▼
(5) FD3D11DynamicRHI::CreateD3D11Texture2D<FD3D11BaseTexture2D>(...)
    │  ← 템플릿 함수 (D3D11Texture.cpp:558), 핵심 로직:
    │  (a) UE 포맷 → DXGI_FORMAT 변환 (PlatformResourceFormat, ShaderResourceFormat)
    │  (b) D3D11_TEXTURE2D_DESC 구성 (Width, Height, MipLevels, Format, Usage, BindFlags)
    │  (c) Flags 처리: RenderTargetable → BIND_RENDER_TARGET, DepthStencil → BIND_DEPTH_STENCIL,
    │      UAV → BIND_UNORDERED_ACCESS, CPUReadback → STAGING
    │  (d) MSAA 설정 (SampleCount/Quality)
    │  (e) 풀링 텍스처 확인 (크기·포맷 일치 시 재사용)
    │
    ▼
(6) SafeCreateTexture2D(Direct3DDevice, Format, &TextureDesc, SubResourceData, &TextureResource)
    │  ← D3D11Texture.cpp:509, SEH 보호 래퍼
    │
    ▼
(7) ID3D11Device::CreateTexture2D(&TextureDesc, SubResourceData, &TextureResource)
    │  ← D3D11 API 직접 호출
    │
    ▼
(8) RTV/DSV/SRV 생성 (Flags에 따라)
    │  ← CreateRenderTargetView, CreateDepthStencilView, CreateShaderResourceView
    │
    ▼
(9) new TD3D11Texture2D<FD3D11BaseTexture2D>(...) 반환
    ← RHI 리소스 객체 생성 (참조 카운팅 시작)
```

### D3D11 특수 사항

- **RenderThread 최적화**: `RHICreateTexture2D_RenderThread()` → 그냥 `RHICreateTexture2D()` 직접 호출. D3D11의 `ID3D11Device`가 스레드 안전하므로 RHI 스레드 대기 불필요.
- **텍스처 풀링**: 동일 크기·포맷 텍스처를 `GetPooledTexture2D()`로 재사용 시도 (정사각형 + 풀링 가능 조건일 때만)
- **SEH 보호**: `SafeCreateTexture2D`에서 드라이버 크래시를 `__try/__finally`로 감싼다 (에러 로깅)

## 4. 추상화 구조의 장단점

### 장점

| 항목 | 설명 |
|------|------|
| **플랫폼 독립성** | 상위 코드가 `FRHITexture2D*`만 다루므로 D3D11/D3D12/Vulkan 교체 가능 |
| **단일 접근점** | `GDynamicRHI` 전역 포인터 + 인라인 래퍼로 호출 코드가 깔끔 |
| **타입 안전성** | `TD3D11ResourceTraits` + `ResourceCast`로 컴파일 타임 타입 매핑 |
| **뷰 일괄 관리** | `FD3D11TextureBase`가 Resource+SRV+RTV+DSV를 한 객체로 관리 → 수명 추적 단순 |
| **유연한 스레딩** | `_RenderThread()` 오버라이드로 플랫폼별 스레딩 최적화 가능 (D3D11은 직접 호출, D3D12는 커맨드 큐) |

### 단점

| 항목 | 설명 |
|------|------|
| **다중 상속 복잡성** | 텍스처: `TD3D11Texture2D<Base> : Base, FD3D11TextureBase` — 계층이 깊고 코드 추적 어려움 |
| **인터페이스 비대** | `FDynamicRHI`에 100개 이상의 가상 함수 → 새 백엔드 작성 시 구현 부담 |
| **D3D11 편향** | Buffer 타입이 VB/IB/SB 분리 → D3D12/Vulkan의 통합 버퍼 모델과 불일치 (UE5에서 `FRHIBuffer`로 통합) |
| **ResourceCast 비용** | `static_cast` 사용 — 런타임 비용 없지만, 잘못된 타입 전달 시 정의되지 않은 동작 |
| **FDynamicRHI 이중 역할** | D3D11에서 Factory + CommandContext 동시 구현 → 단일 책임 원칙 위반 (D3D12에서는 분리) |
| **상태 캐시 중복** | `FD3D11StateCache` + `FD3D11DynamicRHI`의 CurrentXXX 멤버 → 상태 추적이 두 곳에 분산 |

### 프레임워크 설계 시 적용 권장사항

1. **DX11 전용이면 인터페이스 단순화**: `FDynamicRHI` 수준의 완전 추상화는 불필요. 직접 D3D11 타입 사용하되, 핵심 생성/실행 인터페이스만 가상으로 유지
2. **버퍼 통합 고려**: VB/IB/SB를 분리하지 말고 `FBuffer(Size, Usage, BindFlags)` 하나로 통합 (UE5 방향)
3. **뷰 일괄 생성 패턴 차용**: 텍스처 생성 시 SRV/RTV/DSV를 Flags 기반으로 함께 생성하는 패턴은 실용적
4. **ResourceCast 대신 direct 접근**: DX11 단일 백엔드이면 `static_cast` 오버헤드 및 복잡성 제거 가능
5. **상태 캐시는 한 곳에**: `StateCache`와 `CurrentXXX`를 통합하여 관리 지점 일원화
