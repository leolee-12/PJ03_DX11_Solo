## 1. WinMain → FEngineLoop 전체 시퀀스

### 1.1 진입점 (Windows)

```
WinMain (LaunchWindows.cpp)
 └─ LaunchWindowsStartup()
     ├─ SetupWindowsEnvironment()
     └─ GuardedMain(CmdLine)          ← SEH 예외 핸들러 래핑
```

- `LaunchWindows.cpp:199` — `LaunchWindowsStartup()`이 실제 진입점
- SEH 예외 처리로 `GuardedMainWrapper()` 또는 직접 `GuardedMain()` 호출
- 디버거 연결 시 예외 핸들러 우회하여 크래시를 정확히 트랩

### 1.2 GuardedMain — 엔진 생명주기 총괄

```
GuardedMain(CmdLine)                          (Launch.cpp:93)
 ├─ FCoreDelegates::GetPreMainInitDelegate().Broadcast()
 ├─ EngineLoopCleanupGuard 등록              ← 소멸자에서 EngineExit() 보장
 ├─ EnginePreInit(CmdLine)                   ← GEngineLoop.PreInit()
 │   └─ FEngineLoop::PreInit()
 │       ├─ PreInitPreStartupScreen()        ← 코어 모듈 로드, 커맨드라인 파싱
 │       └─ PreInitPostStartupScreen()       ← RHI 초기화, 렌더링 스레드 생성
 ├─ EngineInit()                             ← GEngineLoop.Init()
 │   └─ FEngineLoop::Init()
 ├─ while (!IsEngineExitRequested())         ← 메인 루프
 │   └─ EngineTick()
 │       └─ GEngineLoop.Tick()
 └─ (CleanupGuard 소멸) → EngineExit()
     └─ GEngineLoop.Exit()
```

**핵심**: `GEngineLoop`은 전역 `FEngineLoop` 인스턴스 (`Launch.cpp:28`)

### 1.3 FEngineLoop::Init() 상세 (LaunchEngineLoop.cpp:3946)

```
FEngineLoop::Init()
 ├─ UEngine 파생 클래스 결정
 │   ├─ 게임: UGameEngine (GConfig에서 클래스명 로드)
 │   └─ 에디터: UUnrealEdEngine
 ├─ GEngine = NewObject<UEngine>(EngineClass)
 ├─ GEngine->ParseCommandline()
 ├─ InitTime()                               ← 타이밍 옵션 초기화
 ├─ GEngine->Init(this)                      ← IEngineLoop 전달
 ├─ FCoreDelegates::OnPostEngineInit.Broadcast()
 ├─ PostEngineInit 모듈 로드
 ├─ GEngine->Start()
 ├─ 로딩 스크린 대기
 ├─ GIsRunning = true
 ├─ FThreadHeartBeat::Get().Start()
 └─ FCoreDelegates::OnFEngineLoopInitComplete.Broadcast()
```

## 3. UWorld::Tick() — Actor 틱 메커니즘

파일: `LevelTick.cpp:1273`

### 3.1 틱 전 준비

```
UWorld::Tick(ELevelTick TickType, float DeltaSeconds)
 ├─ FWorldDelegates::OnWorldTickStart 브로드캐스트
 ├─ 네트워크 수신: BroadcastTickDispatch() / BroadcastPostTickDispatch()
 ├─ 시간 업데이트: TimeDilation 적용, FixupDeltaSeconds
 ├─ NavigationSystem->Tick()
 ├─ LatentActionManager.BeginFrame()
 └─ ResetAsyncTrace()
```

### 3.2 틱 그룹 기반 Actor 틱

**ETickingGroup 열거형** (`EngineBaseTypes.h:79`):

```
TG_PrePhysics       ← 대부분의 Actor/Component 기본값
TG_StartPhysics     ← 물리 시뮬레이션 시작 (숨김)
TG_DuringPhysics    ← 물리와 병렬 실행 (비동기, 완료 대기 안 함)
TG_EndPhysics       ← 물리 시뮬레이션 완료 대기 (숨김)
TG_PostPhysics      ← 물리 결과 기반 로직
TG_PostUpdateWork   ← 카메라, 파티클 등 후처리
TG_LastDemotable    ← 마지막으로 내려올 수 있는 틱 (숨김)
TG_NewlySpawned     ← 실제 틱 그룹이 아닌 특수 그룹, 각 그룹 종료 후 새 스폰 항목 반복 실행
```

**실행 흐름**:

```
FTickTaskManagerInterface::Get().StartFrame(World, DeltaSeconds, TickType, Levels)
 │  ← 모든 FTickFunction을 의존성 그래프로 큐잉
 │
 ├─ RunTickGroup(TG_PrePhysics)      ← 블로킹, 완료 대기
 ├─ EnsureCollisionTreeIsBuilt()
 ├─ RunTickGroup(TG_StartPhysics)    ← 물리 씬 시뮬레이션 시작
 ├─ RunTickGroup(TG_DuringPhysics, false)  ← 비블로킹! 물리와 병렬
 ├─ RunTickGroup(TG_EndPhysics)      ← 물리 완료 대기
 ├─ RunTickGroup(TG_PostPhysics)
 ├─ [TimerManager.Tick, TickableGameObject::TickObjects]
 ├─ [카메라 업데이트, 스트리밍 볼륨]
 ├─ RunTickGroup(TG_PostUpdateWork)
 ├─ RunTickGroup(TG_LastDemotable)
 └─ FTickTaskManagerInterface::Get().EndFrame()
```

### 3.3 FTickFunction → AActor::Tick 호출 경로

```
FTickTaskManager가 태스크 그래프에서 FTickFunction 실행
 │
 ├─ FActorTickFunction::ExecuteTick()        (Actor.cpp:165)
 │   └─ Target->TickActor(DeltaTime * CustomTimeDilation, TickType, *this)
 │       └─ AActor::Tick(DeltaTime)          ← 블루프린트/C++ 오버라이드
 │
 └─ FActorComponentTickFunction::ExecuteTick()
     └─ Target->ConditionalTick()
         └─ UActorComponent::TickComponent() ← 컴포넌트 틱
```

**의존성 시스템**: `FTickFunction`에 `AddPrerequisite()`로 선행 조건 설정 가능. TaskGraph가 의존성 순서를 보장하며 병렬 실행.

### 3.4 월드 틱 후처리

```
 ├─ FWorldDelegates::OnWorldPostActorTick 브로드캐스트
 ├─ FinishAsyncTrace()                  ← 비동기 트레이스 완료
 ├─ BroadcastTickFlush()                ← 네트워크 플러시
 ├─ Scene->UpdateSpeedTreeWind()
 ├─ FXSystem->Tick()                    ← 파티클 시스템
 └─ GEngine->ConditionalCollectGarbage() ← 조건부 GC
```

## 4. 렌더링 스레드와 게임 스레드의 분리

### 4.1 분리 아키텍처

UE4는 **게임 스레드**와 **렌더링 스레드**를 분리하여 병렬 실행한다.

```
[게임 스레드]                    [렌더링 스레드]
  │                                │
  ├─ 입력 처리                     │
  ├─ UWorld::Tick()                │ (이전 프레임 렌더링 중)
  ├─ GEngine->Tick()               │
  │   └─ RedrawViewports()         │
  │       └─ Viewport->Draw()  ───>├─ 렌더 명령 큐에 적재
  ├─ FrameEndSync.Sync() ─────────├─ 동기화 지점
  ├─ (다음 프레임 시작)             ├─ 현재 프레임 렌더링 시작
  │                                │
```

### 4.2 핵심 분리 메커니즘

**1) ENQUEUE_RENDER_COMMAND 매크로**

게임 스레드에서 렌더링 스레드로 명령을 비동기 전송:

```cpp
ENQUEUE_RENDER_COMMAND(BeginFrame)(
    [CurrentFrameCounter](FRHICommandListImmediate& RHICmdList) {
        BeginFrameRenderThread(RHICmdList, CurrentFrameCounter);
    });
```

`FEngineLoop::Tick()` 내에서 주요 사용 지점:
- `UpdateAllPrimitiveSceneInfos()` — 씬 프리미티브 갱신
- `BeginFrameRenderThread()` — RHI 프레임 시작
- `Scene->StartFrame()` — 씬 프레임 시작
- `ResetDeferredUpdates` / `FlushPendingDeleteRHIResources`
- `EndFrameRenderThread()` — RHI 프레임 종료

**2) FFrameEndSync (UnrealEngine.h:385)**

```cpp
class FFrameEndSync {
    FRenderCommandFence Fence[2];  // 2개의 펜스로 토글
    int32 EventIndex;
public:
    void Sync(bool bAllowOneFrameThreadLag);
};
```

- `r.OneFrameThreadLag=1` (기본값): **1프레임 지연 허용** — 게임 스레드가 렌더링보다 1프레임 앞서 진행
- `r.OneFrameThreadLag=0`: **완전 동기** — 렌더링 완료까지 게임 스레드 대기
- 2개의 `FRenderCommandFence`를 토글하여 이전-이전 프레임 완료를 보장

**3) RedrawViewports() 호출 시점**

`UGameEngine::Tick()` 말미 (`GameEngine.cpp:1933`):
```
// Render everything.
RedrawViewports();
 └─ GameViewport->Viewport->Draw(bShouldPresent);
```

이 시점에서 게임 로직(UWorld::Tick)은 이미 완료. Draw()가 렌더 명령을 큐에 적재하면 렌더링 스레드가 비동기로 처리.

### 4.3 동기화 타이밍 다이어그램

```
Frame N:
  [Game]  Input → WorldTick → RedrawViewports(큐잉) → Sync(N-1 대기) → 끝
  [Render]          ← Frame N-1 렌더링 중 →          ← Frame N 시작 →

Frame N+1:
  [Game]  Input → WorldTick → RedrawViewports(큐잉) → Sync(N 대기) → 끝
  [Render]          ← Frame N 렌더링 중 →            ← Frame N+1 시작 →
```

## 5. 프레임워크 설계 참고 사항

### 5.1 게임 루프 구조

| UE4 | 프레임워크 적용 |
|-----|----------------|
| `GEngineLoop` (전역 싱글톤) | 엔진 메인 루프 싱글톤 |
| `GuardedMain`의 PreInit→Init→Tick→Exit | 동일한 4단계 생명주기 채용 |
| `FEngineLoop::Tick()` 내 명확한 단계 분리 | 입력→로직→렌더 순서 유지 |
| `while(!IsEngineExitRequested())` | 메시지 펌프 기반 루프 |

### 5.2 틱 시스템

| UE4 | 프레임워크 적용 |
|-----|----------------|
| `FTickFunction` + TaskGraph | 의존성 기반 틱 시스템 (초기엔 단순 리스트 가능) |
| 6단계 틱 그룹 (물리 중심) | PrePhysics / PostPhysics 2단계로 단순화 가능 |
| `FTickPrerequisite` 의존성 | 우선순위 기반 정렬로 대체 가능 |

### 5.3 렌더링 분리

| UE4 | 프레임워크 적용 |
|-----|----------------|
| `ENQUEUE_RENDER_COMMAND` | DX11 커맨드 큐 패턴 적용 |
| `FFrameEndSync` (1프레임 래그) | 렌더 펜스 기반 동기화 |
| `FRenderCommandFence` | `ID3D11Query` 기반 GPU 펜스 구현 |
